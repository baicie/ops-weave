# 来源读取诊断的使用与边界

打开固定发布版本的检查统计时，页面自动读取一次最近观察元数据。只有存在实测来源字段时，列表增加“来源失败 / 尝试”；旧记录显示“—”。选择一条观察后，详情显示完整返回数量、读取时间和闭合原因。所有读取都是元数据 GET，不重新采集，也不核验或重写输出。

来源失败为 1/1、完整返回数量为“—”时，不代表零条数据，也不能计算记录拒绝率。来源成功为 0/1 而转换部分拒绝时，分开查看已检查、未检查与节点处置。异常类别可能重叠，不能加总为总体失败数。

SOURCE_CHANGED 可以进一步说明来源对象、键、值类型或单位发生变化。固定版本拒绝继续输出；先检查当前接入与发现元数据，再通过明确的新版本配置调整固定关系。诊断只保存闭合原因，不提供任意远程请求或原始来源正文。读取前后元数据均检查，历史读取期间发生的变化也拒绝。

未记录来源统计的旧观察保持原 JSON、游标、输出和质量状态。来源成功、转换通过也不能代替输出确认；UNKNOWN 仍须遵守既有只读核验或明确终止流程。

容量仍为每个本人 200 条观察，最近报告最多 20 条，按版本筛选先于数量限制。容量耗尽在来源调用之前失败，不隐藏丢弃观察或自动删除。查看元数据还须拥有当前可信身份及实际对象范围权限；权限失效清除前端私有状态，迟到响应不能覆盖新会话。

排队时长仅在有[实测本地入队/出队证据](workflow-dispatch-diagnostics.md)时显示数值，旧记录仍为“—”。缺少吞吐、租约或生产容量证据时，不能声称生产 SLA 或多副本安全。运行历史、保留策略、生产容量与身份验收继续独立推进。
