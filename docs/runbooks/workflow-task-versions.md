# 更新运行中的工作流版本

先保存、预览并发布新版本。发布不会启动任务或修改旧任务。

1. 查看旧版本的任务及原批次。有运行中的任务先明确停止；有写入待确认或 UNKNOWN 结果先处理原结果。切换版本不会核验、重写或撤回旧输出。
2. 打开更高的发布版本并执行开始采集/启动扫描。新版本用当前控制代数启动，并建立新的读取窗口或扫描；旧游标和确认数量不会被误用为新版本进度。
3. 回执未知时保留原控制 UUID，查询原回执；只有原请求明确不存在时才按既有规则原样确认。不要换 UUID 或刷新页面试图重复启动。
4. 查看旧版本的运行质量，可见原停止/暂停原因与原批次。历史版本无法恢复成当前任务，升级失败或容量不足时不会改变原任务。

待处理批次明确 FAILED 才能升级；主机还要求无已确认实体。READY、IN_FLIGHT 和 UNKNOWN 不能直接绕过；明确终止恢复的版本保留原不确定结果。新资产扫描可能再次读取相同资产，指标/日志新任务从新的窗口开始，不等于历史重放。

旧任务和已停止/失败周期任务的状态通过有界不可变快照保留。每人最多 200 条版本快照；当前没有自动清理或同版本每次运行完整历史。达到上限需保留并报告容量错误，不能删掉历史后静默继续。

本节实现和检查进展见[实现状态](../IMPLEMENTATION-STATUS.md)及[验证报告](../VALIDATION-REPORT.md)。本机真实数据库联测与主平台部署已完成，范围和剩余限制见验证报告第129节。

持续日志仅对明确未写入的拒绝允许恢复/替换。成功写入后的回读失败保留UNKNOWN，V052的私有rejection_known仅由修正后的执行器在明确拒绝时记录；旧记录默认false，不改其原结果体。公开resumeAllowed反映该门禁。旧不确定拒绝的完整质量投影与显式处置尚待后续实现，不把原FAILED视作未写入证明。

§130补充：旧日志FAILED且无明确拒绝证据时，先按未知结果显式终止恢复，再决定是否启动更高版本。更高版本替换校验原终止回执与原不确定父批次；原批次体、日志和质量未知分项保持。新窗口可能与旧未确认输出重叠，不承诺跨版本去重。
