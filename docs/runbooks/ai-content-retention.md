# 本机 AI 内容留存

默认关闭；仅 PostgreSQL。先阅读 [ADR-034](../adr/034-ai-content-retention.md) 的边界。本功能清除当前数据库的过期正文，不能承诺备份、WAL 或磁盘块已擦除。

1. 从 `contracts/examples/ai-retention-policies.json` 复制可信运维配置，设置自己的 tenantId、版本、保留天数和 heldIncidents。先保持 `allowPurge:false`。文件不得由 Web、模型或来源日志提供；不包含密钥。
2. 平台进程设置 `OPSWEAVE_AI_RETENTION_POLICIES_FILE` 为绝对路径。现有 PostgreSQL 启动迁移 V019 回填正文创建/过期时间；上线前仍需独立备份与迁移窗口评估，本机测试不等于生产迁移验证。
3. 为指定人工管理主体配置 `ai.retention.manage` 和全租户 scope。OIDC 仍通过可信身份映射逐请求重新读取授权；开发模式只在 loopback 固定 tenant/随机 token 下验证。不要把这个权限加入模型 Skill 或 Worker 授权。
4. 打开控制台“AI 数据留存”，点击“预览留存清理”。核对租户、操作者、策略、保留 Incident 数量与三类候选数量。日期采用 UTC，严格排除截止边界；有效证据不会因降低保留天数被提前清除。
5. 确认后在可信文件设置 `allowPurge:true` 并更新 version，重新预览。预览 120 秒内勾选确认并执行。本次只执行一批，不自动循环；持久回执显示实际选中数。hasMore 时重新预览下一批。
6. 网络/超时导致结果未知时，用 URL 中的 requestId “查询清理回执”。刷新后需重新认证，只有原主体可读；不会自动重试。404 仍可能是原请求在途，请等待原请求结束后再次查证，不能据此假定未执行。

保留 Incident 必须列出数据原始 incident_id。需要保留合并前后的历史时，同时列出来源与目标。策略每次预览/执行及提交前重读；紧急保留先关闭入口、等待在途请求结束再修改，文件更新与 PG 提交没有共同锁。权限收回从下一请求生效，已通过授权的在途事务受原有预算约束。

回执同键重放在策略关闭后仍返回原结果，因为它不重复清理。正文清理保留原运行 ID、会话唯一、关联、权限范围、请求摘要、费用记录，读取旧结果会重新授权后返回过期；不同输入复用旧 ID 冲突。普通日志不写正文或配置内容。

每类最多 100 条，每租户最多 10000 个回执；达到上限返回 503/READ_LIMIT，需单独评估元数据治理，不能删除幂等记录来“解锁”。没有生产定时清理、费用核销、全平台 tenant 容量上限或备份生命周期实现。测试使用自有随机租户；浏览器链验证新数据不被删除及空批回执，真实正文清除由 PostgreSQL 过期合成数据集成测试验证。
