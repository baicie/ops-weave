# 指标历史窗重放

本地实际来源HTTP验收使用明确Synthetic Fixture与独立测试tenant，步骤和限制见[来源重放验收](workflow-replay-provider-acceptance.md)。

进入数据工作流的运行记录，明确选择具有固定来源及映射的指标发布版本，展开“指标历史重放”。展开仅请求本人元数据，不触发采集或写入。需要可信`workflow.replay`权限及原来源、工作流、指标和实体范围；默认开发身份没有新增权限，403保留为拒绝，不回退Fixture。

1. 输入历史起始时间，点击“检查重放范围”。服务器限制过去24小时、完整60秒且结束至少10秒、最多60条。查看完整指标、固定版本、时间窗、输入/过滤/存储点及摘要。此步没有输出。
2. 明确点击“确认重放”。服务器重新读取同一窗并比较两个摘要，输入变化则拒绝；每个选择只允许一个执行。确认结果进入独立重放系列，持续采集系列、任务状态和checkpoint保持。
3. 响应丢失或不符合契约时，保留原UUID和原内容，点击“查询原重放请求”。明确404后才可原样重发，或放弃本地确认。放弃本地确认不取消服务器请求。
4. 服务端UNKNOWN或PENDING时，明确“核验原输出”；只查询原系列和时间戳，无来源重读/重复写入。早期PENDING保持，UNKNOWN不能视为未写入。刷新记录后选择原UUID，可查回原执行状态。

READY选择10分钟内有效；到期需明确重新检查新选择，不自动换UUID。新选择是独立投影，并非修改旧未确认输出。PREPARING中断保持原记录；此版本没有自动恢复该来源读取，也没有关闭未确认重放的操作，不能将其标成失败或删除以恢复容量。

本人最多200选择，最近20条及按UUID查询保持有界；计数和展示条数不是生产容量或留存保证。精确输出只在内存与既有时序引擎，PG保存证明。当前入口重建指标投影；日志使用独立[历史日志重放](workflow-log-replay.md)。资产重放、覆盖持续系列、自动补偿、通知和动作仍待完成。

部署API/Web与V056同步，仍使用原四单元、受控连接、共享IO预算和时序配置。权限通过已有可信身份grant显式配置，不能改公开默认身份或在URL放令牌。存在选择/执行记录时回退SQL拒绝；先保留记录并评估恢复路径，不对主库做删除或覆盖。生产租约/fencing/多副本及容量仍需独立验收。
