# 终止任务恢复

在已发布固定接入流程的“运行质量与异常”中，当前 FAILED/STOPPED 任务关联原 UNKNOWN 批次时显示终止恢复入口。勾选确认后提交一次。显示已受理表示该任务版本已终止恢复，原输出仍可能已经落库；批次继续显示结果未知，已确认进度保持。

原控制结果待确认时保留请求 UUID，明确点击“查询原终止回执”。查询成功返回原受理事实；查询404后可以原样重发。不要创建另一个 UUID 替代原命令，也不要把网络失败视作命令取消。待确认期间不能关闭页签、切换工作流版本或折叠质量容器。

终止版本不能恢复或重新启动，不能再核验原批次。需要继续采集时创建并发布更高版本，再明确启动；这是新任务和新授权，不重发未知输出、不填补历史空档。旧版本仍可查看终止事件及原 UNKNOWN 批次。

此功能需要平台与 Web 同步部署，以及已有 PG 的 V050 迁移。迁移只增加闭合回执表。服务默认仍为本机 loopback 开发身份；真实端口不可用时失败，不回退模拟数据。

回滚流程：停止处理新恢复状态的应用，导出并保护新回执及任务状态，检查替代版本兼容性，再执行 [V050 回滚](../../db/rollback/platform/V050__workflow_recovery_closure.sql)。旧应用不认识 ABANDONED，不能在任务仍带此状态时直接启动，也不能自动恢复/重写 UNKNOWN 批次。回滚脚本只删除新表，不能作为原输出回滚或业务删除。

当前边界：历史补写/删除/重放、生产租约/fencing/HA、保留策略和生产认证验收未由本功能提供。协议见 [workflow-recovery](../../contracts/workflow-recovery.md)，实际检查见验证报告第128节。

旧日志结果缺少明确未写入证据时（§130），持续日志显示“结果待确认”，质量报告将预期条目保留为未知，可在原任务的终止恢复入口确认并提交。原批次记录可能仍为FAILED，这是保存的历史体，不是安全重写依据。终止后原日志、批次和已确认进度保留；不能把“已受理”当作输出已确认。明确未写入的拒绝继续走原恢复入口。API/Web需同步更新；已有V050/V051/V052沿用，无新迁移。见[ADR-092](../adr/092-legacy-log-outcome-uncertainty.md)及验证报告第130节。

单次指标/日志样本UNKNOWN已由§131的[独立样本终止入口](workflow-sample-recovery.md)处理，不改变任务代数或版本；需要V053，原证明保持未知。
