# 实体工作流后台授权

前提：平台使用postgres与现有OIDC可信身份边界；实体来源仍为当前旧Host批次入口。固定连接配置、指标和日志的持久后台输出尚未开放。本地开发模式沿用固定开发身份，不能代替OIDC身份。

操作员在仓库外准备闭合JSON文件，参照[明确Fixture示例](../../contracts/examples/v2/workflow-background-policy.json)，只列出已经登记到可信身份映射中的外部subject。文件不能增加权限。以私有启动属性`opsweave.workflow.runtime-grants-file`指定绝对路径；Spring环境形式为`OPSWEAVE_WORKFLOW_RUNTIME_GRANTS_FILE`。路径为空时后台授权关闭；文件损坏或缺失时不回退。真实身份、文件和凭据不提交仓库。

用户打开已发布实体版本的“执行与任务管理”，明确来源标识与实体名称，再启动任务。没有后台许可时启动按钮禁用，单次执行仍按现有可信权限检查。授权最长15分钟、最多20批，可能因原登录身份更早到期而缩短。展开“后台授权”查看截止时间、批次额度与授权标识。关闭页面或注销不会自动撤销本次独立授权；要终止处理请停止任务。

上游采集需单独启动。后台每5秒检查启动后完成的批次，每批最多5条；缺失、失败、超限、算子/模型不匹配会停止，且不将失败当作完整空快照。任务固定发布版本和generation，停止与当前代写入串行，旧代不能继续新处理。

授权到期或额度耗尽后，任务显示稳定原因。移除后台许可，或修改/禁用可信身份映射会撤权；文件不可用也会拒绝后续写入。处理失败保留原游标及已经确认的输出ID，查看回执后决定后续操作。当前显式重新启动从新起点开始，不能用它替代失败批次恢复。未知启动/停止结果保留原键并查询原回执，见[任务控制确认](workflow-runtime-control.md)；查询或重放原START不重新签发授权。

重建平台授权适配器不保存或找回登录凭据：它凭任务原引用和当前许可，在原截止内处理原所有者任务。不会将委托任务交给开发轮询，或自动给旧开发任务补授权。任务过期/撤权后不自动续期。若许可及身份同时删除后重启，旧任务不会执行，但可能需管理性对账消除旧RUNNING记录；当前没有跨实例租约与生产恢复保证。
