# 本机来源扫描运行追溯

需现有 PG 与源级 `source.sync`（只有 `entity.read` 会被 403）。V023 只增加一条读取索引，不新增服务、密钥或数据。
先停止旧 writer 后迁移；生产迁移未验收。

1. 打开“来源扫描”，填入平台开发 Token，选择 `Host 扫描` 或 `Item 扫描`，按需要选择每页数量（10/20/50）。
2. 点击“读取扫描运行”读取最近运行；行内可见状态、开始/完成时间、pages/fetched/accepted/rejected、
   `snapshotComplete`、运行自身 `dataMode` 与钉住的映射版本。需要更早的运行就点“下一页扫描运行”，
   `after` 由服务端返回，不要自己构造。
   每行还显示“边界”：`已验证 hostid 水位快照` 表示这次 walk 由捕获的水位与行数验证过（只有此时
   `snapshotComplete` 才为“是”并允许对账），`已验证 itemid 水位快照` 表示指标采集同样完成了水位验证，
   `offset 尝试（无快照证明）` 表示只是 offset 尝试、旧记录，或这次扫描连一页都没读到。
3. 同步响应里的 `syncRunId` 可以直接粘进“扫描运行标识”，点“查询扫描运行”读取那一条。未知、跨租户、
   跨来源或跨对象类型的标识返回 404，不证明“从未扫描过”。
4. 失败运行会显示 `failureCode` 与固定摘要：`SOURCE_FETCH_FAILED` 表示来源请求失败且已存在的实体被保留；
   `CHECKPOINT_FAILED` 表示游标未落库、之前提交的库存可能仍在；`SOURCE_SCAN_BUSY/LOST/DEADLINE/LIMIT`
   表示本次扫描没有拿到或失去了写入资格（Host 与 Item 扫描共用这套码与来源 scope 租约，两个 scope 彼此独立）。
   `SOURCE_SCAN_UNVERIFIED` 表示本次 walk 结束但没有快照证明（上游在扫描期间删除导致行数与捕获计数不符，
   或没看到边界行），因此**不会**对账；已提交的页仍然保留。连接器报告完成却没有水位标签时同样按此处理——
   对账只承认已验证的水位快照。
   摘要只是稳定文案，不是厂商错误原文。
5. `snapshotComplete: false` 表示这次扫描没有做缺失对账：既有资产不会被这次失败删除，也不会被自动修复。
   追溯入口不会重试、续租、对账或清理遗留的 `RUNNING` 记录。
6. 列表上方会显示**扫描日志保留上限**：本范围多少条、本租户多少条，以及本范围当前存储了多少条。
   读取本身不会清理记录；超出上限的运行会在下一次扫描开始时从最旧的已结束运行删起。仍在运行（`RUNNING`）
   或被映射版本钉住的运行不会被删除——如果看到本范围条数长期高于预算，通常是有未结束的遗留运行或钉住的
   历史运行，需要单独排查，而不是反复读取。
   部署侧可用 `OPSWEAVE_SCAN_RUN_MAX_PER_SCOPE`（默认 1000）与 `OPSWEAVE_SCAN_RUN_MAX_PER_TENANT`
   （默认 5000）收紧预算；只能调小，调大或不一致会在启动时被拒绝。
7. 刷新或清除会话后结果会被丢弃，需要重新填入 Token 再读取。凭据只保存在当前标签页内存。

上限为每页 50 条（默认 20），游标由服务端签发；响应禁止缓存。保留预算与清理语义见
[ADR-047](../adr/047-scan-run-retention.md)。实际本机合成数据验证见
[验证报告§44/§54](../VALIDATION-REPORT.md)，不等于已连接真实 Zabbix。
