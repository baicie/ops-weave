# 历史日志重放

本地实际来源HTTP验收使用明确Synthetic Fixture与独立测试tenant，步骤和限制见[来源重放验收](workflow-replay-provider-acceptance.md)。

在工作流运行记录明确选择固定来源的日志发布版本，展开“日志历史重放”。首次展开仅请求本人范围元数据，不读取来源或输出正文。需当前 workflow.replay、source.sync、日志读写及原固定来源/实体范围，默认身份不会自动取得权限。

1. 输入起始时间并“检查重放范围”。窗口限制过去24小时内完整60秒，结束至少10秒，最多1,000条。检查完整来源字段、固定版本、输入/过滤/存储条数、时间与摘要；此步没有输出。
2. 在范围有效的10分钟内“确认重放”。服务器再读同一窗，完整证明一致才写独立重放日志；输入变更拒绝。每个范围只允许一个执行，不覆盖持续日志或检查点。
3. 响应丢失或非法时，保留原 UUID 与内容并“查询原重放请求”。明确404后才允许原样重发或放弃本地确认；放弃不取消服务器请求。UNKNOWN/PENDING不能作为未写入依据。
4. 明确“核验原输出”只读原记录并比较摘要，不重读来源或重复写入。早期PENDING保持；未知结果没有自动补偿或关闭操作。
5. 明确“查看重放日志”，每页最多50条，正文以文本显示，页码操作只读取输出。当前匹配完整性不替代原执行回执；缺失/不匹配保留警示。身份变化清除私有正文与待确认请求。

API/Web与PG V057同步部署。日志库使用同一现有引擎，按 [V003](../../db/migrations/logs/V003__workflow_log_replays.sql) 明确创建独立表；应用账号仅配置该表SELECT/INSERT，DDL由现有迁移管理员执行。未配置或端口失败保留不可用/未知，不回退Fixture。当前范围/执行记录存在时 [PG回退](../../db/rollback/platform/V057__workflow_log_replay.sql) 拒绝，不能删除旧记录来恢复容量；日志投影同样需保留并另行评估，不能直接删除数据表。

本人200范围、最近20条/UUID查询不是留存或生产容量承诺。此功能只重建独立日志投影；原始快照保留、资产修复、旧系列覆盖、通知/动作、未确认重放处置及生产租约/身份/HA仍未由此提供。

参见[契约](../../contracts/workflow-log-replay.md)、[ADR-099](../adr/099-bounded-historical-log-reconstruction.md)及[实际验证](../VALIDATION-REPORT.md)。
