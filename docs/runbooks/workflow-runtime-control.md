# 启动、停止与原控制结果确认

已发布实体流程打开“执行与任务管理”，读取当前任务后显式启动或停止。发布不启动任务，来源采集仍须单独启动。原Host实体后台范围及授权期限见[后台授权手册](workflow-background-authority.md)。

操作成功时页面显示原启动/停止回执和请求编号，并单独读取当前状态。原回执反映受理时快照；若其他窗口已停止或重新启动，以新读取的当前状态管理任务。不要根据旧START回执认定现在运行。

响应丢失或不符合契约时出现“任务控制结果待确认”。此时不改字段、不创建下一版、不重复启动；点击“查询原控制结果”。查询为GET，不签发授权、不重写任务。查询失败保留原编号，没有自动重试；恢复连接后显式再查。

只有明确未找到原回执时，页面提供“按原标识重新提交”和放弃确认。重新提交保持同一UUID、操作、代数和完整输入。若命令已经提交，服务器返回原回执；若尚未提交，则按原CAS尝试受理。409保留确认入口，不能改键绕过冲突。放弃只清除页面确认，不取消服务器或在途请求；先重新读取当前状态再作新操作。

身份变化或403清除页面私有回执；服务器已有任务不会因此自动停止。需使用对应可信身份/范围查询并管理，或由操作员撤销后台许可。浏览器内存中的待确认编号不会写入持久存储；刷新/关闭页面后需用已记录的原编号查询，不能把“列表中有任务”当作原命令确认。

容量满时不自动删除回执。每用户200份控制回执，其中新启动只能使用前180份，预留停止位置；同键重放不占新额度。新START在代数>=999999时拒绝，旧RUNNING即使代数1000000仍能停止，最终STOPPED 1000001不可再启动。容量保留期与清理尚待实现，不能当作生产持续运行配额。

升级需要Web/API一起部署。V041追加现有PG表并登记迁移；runtime-grants.sql只给回执表SELECT/INSERT，生产应由独立迁移角色建表。当前本机检查使用已有测试数据库角色，未验证生产角色拆分。旧无requestId客户端会收到400。

回退前先查询未知命令、停止必要任务并保全原回执。Web/API成对回退；保留V041表不影响旧任务读取。db/rollback/platform/V041__workflow_control_receipts.sql仅作为人工迁移回退文件，不会由启动器运行；删除表会失去原结果确认，不能用作取消。本节开发验证未执行该删除脚本。
