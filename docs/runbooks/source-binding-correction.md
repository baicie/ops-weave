# 本机来源绑定更正

需现有PG、`OPSWEAVE_CMDB_IMPORT_SOURCE`、`OPSWEAVE_IDENTITY_NAMESPACE`与全租户entity.read/entity.manage/source.sync。V022仅增加审计回执表；不新增服务或密钥。先停止旧writer后迁移，生产迁移未验收。

1. 在原资产读取第二来源确认，核对外部ID。若对应来源字段已生效，先在字段审核中撤销。不要删数据库行来绕过绑定。
2. 在正确目标资产人工核对并登记UUID。若只纠正同一资产的登记pin，也必须先登记正确标识。
3. 打开“来源绑定更正”，填写原资产ID、外部ID、目标已登记UUID、新的来源观测时间与字段JSON、原因。新时间必须晚于该来源已保存快照；原始历史值不能当成一次新采集。
4. 点击“读取更正预览”，核对租户/来源、原与目标资产、两个版本、UUID及新观测。变更输入会取消原预览；明确确认后提交一次。
5. 冲突时重新读取状态；生效字段冲突需先撤销。超时或结果未知，查询原请求ID；404不证明写入失败，不据此创建新请求重发。
6. 刷新后重新登录并显式查询原回执。按原或目标资产ID读取更正历史，可见当时操作者/原因与原归属。新字段仍在目标资产待审；原观测/指标/Incident/证据不迁移。

更正会使原资产失去该来源的存在保护；若主来源也已缺失，原资产会变为INACTIVE。目标仅依据新的合格来源观测获得确认。旧快照回执不会被改写，历史归属不能当成当前绑定。不同namespace/配置来源的迁移、实体合并和历史重算不在本入口内。

上限为每来源/租户1000份更正回执，同时受快照留存1000份限制；没有自动清理。实际本机合成数据验证见 [验证报告§43](../VALIDATION-REPORT.md)，不等于已连接真实CMDB。
