# 工作流质量阈值配置与核验

选择已发布工作流的固定版本，展开“运行质量与异常”中的“质量阈值”。活动页的可信会话就绪后首次展开读取一次。未配置时规则未启用；选择规则、填写阈值及统计区间，再明确保存。已发布流程本身不会因阈值配置而改变。

| 规则 | 依据与显示 |
| --- | --- |
| 连续来源失败 | 最近实测来源端口结果；缺少 sourceRead 不当作成功 |
| 连续输出拒绝 | 最近明确拒绝输出的批次；未知、待确认及未证实旧失败不计拒绝 |
| 排队时间峰值 | 本地 dispatch 实测等待；同次出队跨窗口去重，不代表端到端延迟 |
| 当前任务失败 | 当前精确版本任务的 FAILED 状态；没有当前任务时无法评估 |

“未达阈值”只表示当前这条规则的证据未触发，不是接入或整体健康结论。“无法评估”显示“—”并给出没有观测、缺少测量、历史截断、没有当前任务或顺序不明的原因。相同时间混合成功/失败不能按 UUID 猜测先后。触发时仍检查缺失及截断提示，查看依据 UUID 后，可在既有诊断或质量查询中读取原证据。

统计区间为 60 至 86,400 秒，但本次最多读取最近 20 条。连续次数达到阈值后停止计算，不代表完整区间总失败次数。实际零与缺失分开。改变统计区间或阈值只保存配置，不重读来源、不重新输出，也不补写旧测量。

保存遇到 409 时保留本地草稿，不自动覆盖别人或其他页签的配置。撤销修改后可明确刷新，读取最新配置再编辑。丢失/非法回执或服务失败时保留原 UUID，点击“查询配置回执”；仅明确 404 后提供“原样重发配置”及“放弃本次确认”。放弃不撤销服务器写入，不改 UUID 后自动重试。未保存、保存中和待确认会阻止折叠/关闭。403 清理私有页面，需要重新建立可信会话；迟到响应不会恢复旧配置。

取消全部勾选并保存可停用规则。启用/修改最多占用本人前 199 个不可变回执，第 200 个保留给停用；到达上限明确报错，不能清理回执规避容量。旧回执持续可查询，不能用当前配置冒充当时接受结果。

部署时同步更新契约、Web 与平台，确认包内 V054 资源及启动登记齐备。迁移只增加现有 PG 的两张元数据表。回滚脚本会删除阈值配置与回执，只在独立测试 schema 完成前进→回退→前进验证；实际业务环境回退前必须导出并审查，不能用回滚解决损坏记录。配置内容与 SQL 标量、父版本摘要或时间不一致时服务明确失败，保留原记录调查。

本功能没有通知接收人、自动推送、动作执行或生产 SLO 承诺。重放、检查点停滞、预算耗尽、租约冲突、保留与生产容量需后续验收。见[契约](../../contracts/workflow-quality-alerts.md)、[决策](../adr/096-configurable-workflow-quality-thresholds.md)和[验证报告](../VALIDATION-REPORT.md)。
