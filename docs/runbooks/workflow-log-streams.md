# 固定日志持续采集

打开已发布的固定日志流程，展开“持续日志采集”。首次可见读取状态。开始后显示确认至的时间、累计窗口/记录数、本次批次额度和最近窗口；日志样本写入保留独立入口。

首次开始选择最近 60 秒窗口，等待 10 秒稳定期；后续从最后确认时间继续。每窗口最多 1000 条，完整来源分页失败或超限时保留进度，不写成功前缀。下一窗稳定后回看上一分钟，新增日志单独显示“迟到补采”。旧记录缺失或内容变化会暂停，禁止自动覆盖。更早迟到数据尚无自动修复入口。

停止保留原版本和 checkpoint。恢复从原进度继续且需要新的限时授权；开发任务也最多 20 批。非开发后台最长 15 分钟/20 批，退出会话后仍独立运行，可重新登录停止；额度到期需显式恢复。

写入待确认或结果未知时先“核验原批次”。核验只读原日志批次，不重读来源或重发输出。完整匹配后确认并保持停止，再明确恢复；未匹配不能重发或跳过该窗。明确拒绝可恢复并重新读取同一窗口，旧失败证明保留。

“查看日志”每页读取 50 条，通过上一页/下一页浏览。确认记录数是全批次计数；读取时间说明本次回读时间，与任务确认时间不同。若原批次尚未完整匹配，保留提示，不把当前页当作完整数据。正文保持空白、换行与 Unicode，以纯文本展示。采集位置保留纳秒，事件时间可由映射单独定义。

控制响应丢失保留原请求，查询原控制回执；原 404 后才允许重发相同内容。放弃本次浏览器确认不会取消服务器操作。失败或契约异常停止自动刷新，身份变化清理原正文和迟到响应，隐藏页面也清理正文缓存。没有自动来源重读、输出重试、授权续期或未知放弃。

配置和迁移沿用[日志存储说明](workflow-log-output.md)，增加现有业务库 V048 元数据表，不重新初始化 Docker 卷。本机验证不代表分布式 HA、生产负载或耐久性验收。
