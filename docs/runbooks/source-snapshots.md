# 本机来源快照操作

该功能需要 PostgreSQL、已有 `OPSWEAVE_CMDB_IMPORT_SOURCE` 与 `OPSWEAVE_IDENTITY_NAMESPACE` 配置，以及 tenant-wide 的 `entity.read,entity.manage,source.sync`。不需要新数据库、服务或凭据；memory或未配置时503。V021迁移只在现有PG执行，生产迁移未验收，需停止旧写进程。

1. 在资产详情人工核对并登记规范UUID，确保同一租户/命名空间唯一。未知UUID不会由快照接口猜测或创建资产。
2. 打开“CMDB快照”，显式读取配置，核对租户/操作者/来源。输入来源观测时间与records JSON，最多100条/浏览器64KiB。
3. 每条例如 `{"externalId":"asset-1","assetUuid":"51111111-1111-4111-8111-111111111111","values":{"owner":"Ops"}}`。这是形状示例，只有已登记的实际测试UUID才可定位。字段只允许name/ip/owner/environment。
4. 只有能确认该来源完整权限与完整采集时才勾选完整快照；空完整快照也会将该来源所有已知绑定标为缺失。部分输入不勾选完整。
5. 核对后提交一次，保存requestId。超时/未知结果先查询原回执，页面不自动重试。刷新仅恢复requestId，凭据和正文不持久化；原actor重新登录后显式查询。
6. 进入目标资产读取“第二来源确认”和“补充来源字段审核”。快照只生成待审字段。已有生效字段需先撤销，再导入新的观测时间/请求建立当前版本的待审记录。

未知UUID、目标绑定冲突、旧时间、请求复用均整批失败；不会继续用空数组对账。不要为了绕过上限而删除数据库绑定/回执。原外部对象确需纠正目标时，使用独立的[来源绑定更正流程](source-binding-correction.md)，提交新观测并保留原审计；普通快照不能隐式重绑。来源/命名空间迁移、已有资产合并仍不提供。

presence的判断以响应evaluatedAt为准。PRESENT也只是来源确认存在，不表示服务健康；ABSENT表示该来源完整导入未见，连续完整导入会刷新缺失确认时间；STALE表示7天失效（包括过期的缺失确认）；IDENTITY_REVOKED表示原登记撤销。空列表只是没有该来源记录。Zabbix状态、指标数据缺失与字段来源仍需分别查看。

验收通过自有随机租户和合成输入进行，实际证据见 [验证报告§42](../VALIDATION-REPORT.md)；这不等于已连接真实CMDB或完成生产HA/容量验收。
