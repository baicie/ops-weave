# 使用数据工作流

入口：本地 http://127.0.0.1:5173/#/integrations/workflows ，左侧“数据接入 → 数据工作流”。当前复用开发会话或已有可信平台会话，仍由服务端逐请求授权；本地Token只保留当前标签页内存。

1. 点击“读取工作流”，载入模型、草稿、发布版本和本人的运行记录。
2. 选择“自定义实体模板”或“Zabbix主机模板”。前者默认内置Service，也可选择已发布自定义实体模型；后者固定到配置中的Zabbix来源。变更目标模型会重建默认映射和清洗链。
3. 点击左侧节点添加清洗步骤，在右侧配置字段、默认值、枚举、系数、过滤条件。用上移/下移改变执行顺序，拖动只改变布局；连线自动随执行顺序生成。可撤销、重做或自动排列。AI协助入口暂未启用。
4. 点击字段映射节点，把来源字段对应到目标字段。手工填写1到5条JSON记录；模板里的示例明确为Fixture。Zabbix填写“来源扫描”页已有Host采集批次ID，此操作不触发新采集。
5. 保存草稿后点击“预览当前草稿”，选择节点查看这一阶段的结果。通过、拒绝、过滤分开计数；缺失Raw、样本截断、来源模式及批次失败状态保留。样本不随草稿持久化。
6. 至少1条通过且无拒绝，15分钟内可“发布版本”。修改语义规则后重新预览；移动坐标不改变语义。发布不会启用采集或写入实体。
7. 发布后定义只读，可以“测试运行已发布版本”或“创建下一版”。刷新并重新授权后从已发布列表打开；运行历史保留回执及新运行的逐条节点状态/错误原因；输入和输出正文不保存，逐步输出需再次显式测试运行。

网络结果不明时先重新读取草稿/已发布列表核对。保存使用editVersion防止覆盖；原样发布重试会返回同一版本。测试运行没有隐藏重试，每次显式执行新增一份回执。放弃本地修改恢复最后保存版本，未保存的新模板会被关闭。

当前上限：50个活动草稿/用户、200份运行回执/用户、200个发布版本/租户。满额明确报错；本段未实现回执保留清理、全部历史分页或运维删除入口。

现有v1接入流水线与历史版本继续使用旧入口。v2目前只产出转换预览，不自动新增/更新自定义实体或关系，不接通用HTTP、脚本、模型节点或修复动作。Zabbix版本差异继续由已有Java连接器和v1映射适配，画布不能绕过它；本轮读取的是本地7.0.27已有批次，不能推断其他厂商版本已验收。

数据库升级：由迁移所有者应用V029；受限平台运行角色使用db/security/runtime-grants.sql补齐workflow_draft的SELECT/INSERT/UPDATE以及workflow_version/workflow_run的SELECT/INSERT。已发布版本和回执不给UPDATE/DELETE。四个启动单元不变。工作流基础验证见VALIDATION-REPORT §70，运行记录增量见§73；设计见ADR-055与ADR-057。

新建推荐入口为[数据源中心](source-center.md)：选择类型→配置抽屉→确认保存→打开初版画布。工作流页仍可直接创建模板；旧v1 Host流水线继续保留。接入方案不是自动采集绑定。

## 查看成功、失败与过滤明细

进入“数据接入 → 工作流运行记录”，授权后读取最近20次预览/版本测试。按转换结果或工作流/运行ID筛选当前列表，点击“查看明细”查看计数、来源与模型版本、执行耗时、节点统计和逐条结果；失败记录默认展开，提供字段、中文原因及稳定错误码。也可以输入完整运行UUID回查更早记录。画布下方每条运行回执可直接跳转详情。

失败后的节点标记未执行；过滤是按规则跳过，不计失败。转换全部通过仍不代表来源完整或实体写入；上游失败、缺失Raw和截断会另行提示。刷新后用原会话重新授权读取即可，读取不重新执行、不调用模型。旧回执仅有计数时页面明确提示没有逐条明细。

历史记录不保存样本/节点输出正文；当前画布节点输出仍仅本次响应可见。请求级错误（例如非法JSON、鉴权失败、来源读取失败）暂不形成持久运行详情；本入口是v2工作流测试运行历史。

画布现由 AntV X6 渲染：拖动节点改位置，拖空白平移，普通滚轮滚动页面，Ctrl/⌘+滚轮缩放；“适应”显示全部节点。改变执行顺序仍使用配置区的上移/下移，连线不开放任意编辑。菜单已将旧v1入口改为“接入维护 → Host 采集维护”；详见[图形与导航说明](graphs-and-navigation.md)。
