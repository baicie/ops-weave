日期：2026-09-27。状态：整体需求设计；§68已实现模型定义与清洗预览第一段，§70已实现原生v2单链工作流及只读测试画布，其他能力按阶段推进。本文不代替验收报告。

## 2. 内置能力先可用，自定义并列提供

### 2.1 内置实体模型与关系模板

首版模型包计划覆盖Host（主机）、Application（应用）、Service（服务）、Database（数据库）和NetworkInterface（网络接口）。内置公共字段包括显示名称、说明与适用的业务属性；平台ID、租户、对象版本、生命周期、来源/观测/血缘是系统字段，不能由普通自定义字段覆盖。

内置关系模板计划包括应用包含服务、服务部署于主机、服务依赖数据库、主机包含网络接口。关系类型约束方向、起点/终点类型及基数；实际关联必须由可追溯数据或有权用户明确建立。安装模型包不创建演示主机、数据库或依赖边，不从同名/IP臆造关系。

这些是类型定义与模板，不代表已具备相应厂商连接器或真实实例。当前真实接入仅按已有实现报告；Service/Database等类型本身也必须开发和验收。

### 2.2 内置指标目录

| 定义 | 首批接入基线 | 必须保留的语义 |
|---|---|---|
| 主机CPU用户态占比 | 已有host.cpu.usage.user，Zabbix user CPU映射 | Gauge、比例0–1；不能改称总CPU利用率 |
| 主机可用内存比例 | 已有Zabbix内存可用比例映射 | Gauge、比例0–1；可用量与已用量不能混名 |
| 系统运行时长 | 已有Zabbix uptime映射 | Gauge、秒；不能当作累计事件计数器 |
| 磁盘容量/使用率、网络收发等常用指标 | 后续补齐并逐项验证定义与映射；未接入时显示未配置/无数据 | 字节/比例、累计量/速率、方向、维度、counter reset策略分别定义 |

首版至少复用已验证的三项指标作为开箱基线，并提供指标目录页面、适用实体类型、来源绑定与采样可用性。内置定义、来源配置、实际采集状态分开显示；没有采样就显示无数据，不填演示数值。后续增加预置指标须登记完整语义和支持范围，不为了凑数量创建不可解释的指标。

指标目录支持受控自定义定义；类型、单位、Gauge/Sum等语义、适用实体类型、允许维度、定义版本均由服务端校验。新增指标不等于新增采集器；真正取数仍需已支持的来源绑定。重用既有MetricDefinition/MetricSeries边界，高频采样继续写时序库，不逐点执行模型或持久工作流。

### 2.3 自定义实体类型与字段

- 创建类型标识、显示名称、说明、字段和身份规则；用稳定字段标识区分“改显示名”与“删除后重建”。
- 第一版字段以有界类型为基础：文本、整数、十进制数、布尔、枚举、日期时间，以及有界列表/结构化字段。限制长度、数量、深度、值域和必填；不接收任意JSON Schema执行能力、远程引用、脚本校验或无限递归。
- 业务可新增类型，也可给内置类型增加租户扩展字段。扩展固定baseType版本，禁止覆盖内置字段身份、语义及系统元信息。复制类型时得到新类型标识，不能冒充内置类型。
- 草稿不参与正式写入；发布生成不可变模型版本和digest。实体和Observation记录所用模型版本，API、采集器、人工维护均执行相同校验，不能只靠前端动态表单。
- 源字段、原始观测、用户模型属性和平台来源元信息分开保存/返回，模型字段不能覆盖tenantId、来源实例、Raw引用、映射版本或权限字段。
- 第一版不创建任意数据库表，不把字段名拼成SQL。模型与关系仍由现有catalog/inventory模块和PG适配承载；跨语言协议新增于contracts。

### 2.4 版本兼容与迁移

内置定义固定版本，发布新版本不覆盖已有版本。租户扩展、用户实体类型、指标定义和关系类型同样使用草稿/发布版本。保存草稿的editVersion与发布revision分开，比较并交换防止覆盖他人修改。

新增可选字段可作为候选兼容修改；新增必填、收紧枚举、字段类型/单位/身份规则或关系端点/基数变化必须做影响检查。未完成明确迁移前，旧实体/关系/流水线继续引用旧版本。停用版本阻止新绑定，保留历史读取；有引用时禁止硬删除。

现有Host v1记录与已发布流水线必须可回读，不能在读取时补写成“已经过新模型校验”。先建立明确的legacy适配和迁移入口。现有ExternalLink已绑定的对象若被新流水线映射为不兼容类型，产生冲突，不默默换类型、合并、复制或重定向既有实体。

## 3. 数据源中心与配置抽屉

数据源模板描述连接器id/版本、支持的对象类型、配置字段与凭据要求、受支持的厂商版本/分页能力和服务器能力状态。客户端不能加载任意连接器包；“CMDB快照导入”明确是导入适配，不标为已经连接某个CMDB API。

抽屉按连接器渲染：实例名称、连接地址、受控凭据引用、对象范围/过滤配置、采集选项及所属配置权限；不要求目标模型，输出类型和实体模型留到工作流选择。多个Zabbix实例具有不同sourceInstanceId，不能共享Host/Item外部标识空间。

凭据编辑以选择已有secretRef为基础；如提供录入/替换，走后端专用只写通道，响应只返回引用/掩码，草稿/画布/浏览器持久存储/日志/AI上下文均不保存凭据明文。连接测试必须经过Java的授权、网络目的地准入、超时/响应大小限制；表单地址不是任意HTTP代理。保留本机loopback开发限制和显式fixture模式。

连接测试回执绑定实例及配置版本，修改地址/凭据/对象范围后旧成功结果不再表示当前配置可用。测试失败保留明确失败状态，用户可保存未完成草稿，不回退mock。确认时使用幂等请求标识和预期版本，失败保留输入，重复确认不创建重复实例/草稿。新来源与工作流是可独立恢复的两次显式操作：来源确认回执稳定，草稿保存失败可重新进入输出配置。旧实体初始化继续同事务，不用无保护写入拼接假成功。

## 4. 画布与确定性转换

### 4.1 界面布局

- 顶栏：来源/目标模型及固定版本、草稿/未保存标记、保存、校验、预览、版本差异、发布。
- 左侧：当前服务器允许的节点库、目标模型字段与输入字段。能力未实现的节点不可拖入可执行图。
- 中央：有界节点图，移动/连接/删除、缩放/适应视图、撤销/重做；提供键盘可操作的节点/步骤列表，不以鼠标拖拽作为唯一配置方式。
- 右侧：选中节点属性、输入输出Schema与字段匹配；预留可切换的AI建议侧栏，默认未启用，不展示假聊天/生成结果。
- 底部：明确来源和模式的样本、当前节点输入/输出、目标模型预览、错误/丢弃原因、血缘。空值、字段缺失和转换失败分别展示。

桌面及窄屏延续现有shadcn-admin主题、React/shadcn/ui组件和X6适配器；阶段导航、节点步骤列表与属性配置共同完成编辑。图形库不进入跨语言业务Schema。

### 4.2 节点与执行范围

首批可执行流程：来源记录 → 解析 → 清洗/转换 → 字段映射 → 模型校验 → 身份解析 → 写入Observation并更新实体。清洗/转换包括显式重命名/提取、文本trim、空值策略、类型转换、枚举映射、时间解析、单位换算和有界过滤；仅实现并登记的确定性算子可用。默认值必须显式配置并留下血缘，不能用猜测填补缺失数据。

清洗节点可增删和排序，执行器验证阶段依赖和端口类型。首版以单来源主链及有实现支持的输出为界；循环、无界分支/Join、远程节点、任意SQL/JavaScript/Shell、模型逐记录转换都不支持。图上不能连出后端无法执行的流程。RelationObservation输出在关系领域/解析完成后作为受控输出加入，不借用普通Entity写入去伪造关联。

字段路径和转换配置来自受限表达式，不进行eval、远程Schema下载或访问文件。所有节点数量、图深度、样本数、字节、耗时和批次上限落入服务端契约与负例检查；前端限额不是执行器限额的替代。

### 4.3 定义、布局与发布

现有v1严格固定6节点/5边且只有displayNameField一个映射选项，不能直接承载该画布。新增v2定义与适配，保留v1读取/执行/digest，不修改历史发布内容。

业务定义固定sourceInstance/config revision、连接器版本、节点算子版本、目标实体/关系/指标定义版本、映射和错误策略；布局只保存节点坐标/视口/折叠状态，不能进入业务执行语义。布局变更不冒充重新预览后的映射变更。表单、画布与以后AI建议共同修改一份规范化定义，不维护三套真相。

Preview默认使用已授权、明确选择的Raw样本；需要新样本时显式发起有界来源读取并标注是否持久化Raw，不能把网络抓取藏进一次画布拖动。预览不写Entity/Relation、发通知、开始同步或调用模型。

发布由服务端复核权限、定义digest、editVersion、来源配置/目标模型/算子版本与有效预览回执。任何语义变化或版本失配要求重新校验/预览。现有Host发布入口的页面预览顺序不是服务端发布门禁，不能声称已覆盖此要求；v2必须补齐并测试绕过UI的直接调用。

发布产生不可变版本；启用显式切换来源绑定，已开始运行固定旧版本直到结束。重放仍默认dry-run，不能把新画布发布等同于历史写入修复。上游失败和过滤丢弃都不能被当作完整空快照去删除资源，缺失对账须使用独立、明确的完整性证明。

## 5. 实体关系管理

模型中心定义“允许什么关系”；关系页面管理“哪些具体实体存在该关系”。列表/详情是第一版必交付，拓扑是同一批受权数据的辅助视图，不能单靠可视图维护业务。

关系记录包含固定的关系类型版本、两端实体、来源或人工断言依据、有效起止时间、观测时间/摄入时间、状态及对象版本。查询两端实体都要授权；不可用端点不能通过节点名称、边计数或搜索提示泄漏。拓扑只返回受限层数/节点数/边数，裁剪和不可见范围明确表达，不能展示成完整依赖图。

人工创建/更正/终止关联需理由、服务端校验和幂等请求；类型方向、两端类型及基数在事务中检查。来源关系使用独立Observation：一个来源失效不抹掉其他来源仍确认的关系；人工断言不改写来源原文。端点无法解析时进入待处理状态，不按名字/IP猜测。来源记录与人工断言的冲突要可见，采用明确策略，禁止最后写入者静默获胜。

终止关联设置有效结束时间或追加撤销记录，保留历史，实体软删除不级联破坏旧Incident/Evidence。关系变化不重写旧证据快照；将来诊断消费拓扑时必须新增版本化Tool/Schema和失效复核，当前只读Skill不自动获得拓扑权限。

## 6. AI协助扩展位（以后实现）

现在预留界面与协议边界，不调用模型、不增加新AI服务或可写工具。入口受服务器Capability控制，缺能力时明确“未启用”。后续可提供解释节点、建议字段映射、根据Preview错误建议修正等能力。

候选上下文只包含当前受权草稿的id/editVersion/digest、固定目标模型版本、当前节点/字段、校验错误和用户明确允许的脱敏有界样本。凭据、原始授权头、未授权数据、完整原始日志和可任意外连地址不能进入助手上下文。

建议输出是绑定base editVersion/digest的白名单定义Patch、逐项理由和待验证项；不会返回可执行代码、直接写数据库、连接数据源或发布配置。用户逐项接受后只修改草稿，随后重新Validate/Preview并走相同发布流程。草稿已变、越权、模型版本变化、非法节点或预算不足都拒绝应用建议。

AI的将来实现由Rust经受控平台API读取上下文并遵守共享预算；Java继续承担保存、校验、预览和发布。与Incident只读诊断、Skill DAG和修复动作分开，不让一个画布变成万能执行引擎。
