# ADR-095：本地工作流调度的实测排队时间

状态：已接受。日期：2026-10-05。

持续指标、日志及固定连接主机任务在一个本人的轮询内按顺序执行。后面的任务可能等待前面的来源 IO；窗口迟到、来源读取耗时和实际排队时间需要分别记录。

沿用 Java 平台的现有调度器、IO 并发预算及存储，在一次轮询取得预算和本人任务快照之后，将符合运行状态与授权类型的任务放入本地 FIFO。每次入队分配随机 dispatch UUID 并记录时间，出队开始处理前再记录时间。当前 PG 本人查询最多返回 21 个任务，本地队列容量对应为 21；超出容量明确失败，不能静默截断。没有新增线程、独立执行器、持久队列、数据库或启动单元。

Dispatch 保存 id、enqueuedAt、startedAt 三个闭合字段。queueWaitMillis 为出队时间减入队时间的整数毫秒，不足 1 ms 的实测值为 0。时间倒退、超过一小时、标量不一致或开始晚于父检查开始均失败，不夹紧、猜测或补零。观测只覆盖当前轮询内被接收的等待区间，不包含取得预算之前、前次轮询、全局积压或来源 IO 耗时；不能作为端到端延迟或生产容量证明。

队列携带不可变任务快照，但快照不是授权。执行器在来源 IO 前继续查询当前任务、代数、固定版本、可信身份及授权时效；排队期间 STOP 或授权过期的旧任务不能读取来源。原租户、对象范围、观察容量、确认游标及输出证明门禁保持。一个出队任务可能检查上一分钟与当前窗口，两条观察共享 dispatch UUID 与等待时间，不能相加为两次排队。

沿用 V049 的有界 JSON。旧 13 字段观察和仅有来源统计的 14 字段观察可读；缺少实测 dispatch 的公开投影省略该字段并保留 queueWaitMillis=null。新观察同时有来源与调度统计时为 15 字段。没有历史回填或数据迁移，损坏 JSON 失败，不当作空成功。Schema、领域、存储及 Web 分别执行相应闭合和跨字段校验。

Web 的 WorkflowDispatchDetail 只显示入队及开始执行时间，读取仍由既有诊断请求容器持有。没有新增自动请求、来源读取或写入按钮。缺失为“—”，实测零与缺失分开。

多副本租约/fencing、跨本人公平调度、轮询完整性、保留、生产容量与时钟纪律仍需独立验收。本地 FIFO 不提供上述保证。见[契约](../../contracts/workflow-dispatch-diagnostics.md)、[操作说明](../runbooks/workflow-dispatch-diagnostics.md)及[实际验证](../VALIDATION-REPORT.md)。
