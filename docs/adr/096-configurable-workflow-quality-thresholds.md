# ADR-096：固定工作流版本的显式质量阈值

状态：已接受。日期：2026-10-06。

连接测试、来源读取、输出确认与当前任务状态各有不同证据。操作人员需要配置具体阈值，并看到本次判断所用的范围、缺失和截断情况，不能由绿色标签推断整体健康。

沿用 Java 平台、既有 PostgreSQL 和四个启动单元。纯领域 `WorkflowQualityAlerts` 接受质量与诊断快照，只计算元数据；应用服务只持有 Store、Clock 和现有授权读取服务，没有来源、输出、通知或动作端口。V054 保存本人、租户和固定发布版本的当前配置及不可变命令回执。平台启动必须登记迁移，构建必须将同一仓库 SQL 作为资源打包。

规则默认未启用，由用户明确保存。统计区间为 60 至 86,400 秒，读取最近 20 条有界证据。规则包括连续来源失败、连续已证实输出拒绝、实测本地排队时间峰值及当前精确版本任务失败。前两项阈值为 1 至 20 次，排队阈值为 1 至 3,600,000 ms，任务失败阈值固定为 1。停用保存空规则，未配置与已停用分别展示。

连续次数从最新证据向前计算，成功终止连续失败，达到阈值即停止计数；返回值是已证实达到的次数，不宣称完整失败总量。缺失或未证实拒绝不能按成功重置，历史截断后仍不足阈值不能判定未触发。同一时间有失败、成功或缺失的混合证据时，UUID 排序不能证明先后，返回无法评估。排队峰值按 dispatch UUID 去重，同次出队的两个窗口只计一次；已知峰值足以触发时仍保留缺失数量和截断标记，不足阈值且证据不全时无法评估。当前任务规则读取当前精确版本状态；旧归档任务不能替代当前任务。

状态为已触发、未达阈值和无法评估。未知值保持 null，Web 显示“—”。未达阈值只对应这条规则，不代表总体健康。查询在同一个租户事务中取得配置、质量、诊断及同一个 asOf，规范时间截断至微秒；损坏或不一致的证据失败，不能返回空成功。

配置使用 expectedVersion 乐观并发控制、随机原 UUID 和规范命令摘要。原 UUID 与原内容重复请求返回原回执，异内容冲突；回执可在后续配置变更后原样查询。每本人最多保存 200 个回执，启用或修改规则最多使用前 199 个，最后一个容量保留给空规则停用。该上限不是生产保留策略，达到上限明确拒绝，没有静默清理或隐藏重试。当前可信身份及固定来源、目标、对象范围在每次读写服务器侧复核，请求不得携带 tenant、owner 或权限。

Web 由 WorkflowQualityAlertsSection 持有请求、配置草稿、原命令、会话隔离和关闭门禁，WorkflowQualityAlertsPanel 只展示。第一次展开且活动会话就绪后读取一次，保存后读取一次最新状态；失败不自动重试。丢失或无效回执保留原命令，先查询原 UUID，明确 404 后才允许原内容重发或放弃本次本地确认。后者不取消服务器命令。未保存及待确认状态不能折叠或关闭，身份清理丢弃迟到响应。

本节不签发后台授权，不推送通知，不执行动作，不扩展高基数监控标签，不声明生产 SLO。检查点停滞、预算耗尽、租约冲突需要各自可验证证据；通知接收人、规则去抖、保留与容量、多副本租约/fencing 和独立生产身份仍需后续设计及验收。见[契约](../../contracts/workflow-quality-alerts.md)、[操作说明](../runbooks/workflow-quality-alerts.md)及[实际验证](../VALIDATION-REPORT.md)。
