# ADR-055：原生、有界的数据转换工作流

日期：2026-09-27。状态：已接受，首段实现。承接 ADR-054 与用户“可以实现工作流”。

## 决策

在现有 Java 平台内实现独立 v2 转换定义、执行器和 PG 元数据，不部署 Dify 或通用工作流服务。Zeus Web 提供原生画布：节点库、位置拖动、顺序调整、配置、撤销重做、样本及逐步输出。首版只支持单条主链，节点顺序决定执行顺序，连线自动生成；禁止环、分支、循环、任意代码及 HTTP 节点。

v1 Host 流水线与已发布历史保持兼容。v2 输入为手工样本，或经现有 v1 Host 预览边界授权读取的已有 Zabbix 保留批次；不是新增 Zabbix 连接器，也不触发实时采集。目标固定到内置或已发布自定义 ENTITY 模型的 id、revision、digest。指标和关系输出、模型实例写入不在本段启用。

执行拓扑固定为 SOURCE → MAP → 0到12个受控清洗节点 → VALIDATE → OUTPUT，总共4到16节点。仅提供 TRIM、EMPTY_TO_NULL、DEFAULT、ENUM_MAP、SCALE、FILTER。VALIDATE 复用 safe-scalars-v1。所有执行均为 dryRun=true、writesPerformed=false，不持有资产写入端口、模型或动作端口。

## 版本和存储

使用 integration.workflow_draft、workflow_version、workflow_run 三表（V029），复用现有 PostgreSQL，不新增数据库。草稿按可信 tenant+subject 隔离，以 editVersion 比较并交换保存；版本在租户内不可变、连续递增。发布后的内部草稿保留用于幂等发布确认，从可编辑列表排除。

节点语义、目标 pin、来源、名称、revision 进入 SHA-256 digest；画布坐标独立保存。语义变化清除旧预览回执；只移动坐标保留回执。发布要求当前草稿的服务端预览：至少一条通过、无拒绝、回执未过期（15分钟）且非未来时间。少量通过的样本只证明此样本上的转换，不证明上游完整、生产可靠或根因成立。

运行记录仅保存版本引用、定义/输入摘要、来源标记、计数和时间；不保存手工样本、逐步输出或客户原始数据。刷新后可查回执，查看值需再次显式测试运行。执行不重试、不回退；超时后可读取列表确认，重复显式测试会新增回执。

## 边界

workflow:* 资源范围与 source.sync 权限由 Java 检查；模型读取另需 catalog:* / entity.read，Zabbix 批次继续执行来源与每个实体的权限检查。身份不接受请求覆盖。每次1到5个样本、每条32字段、字符串2048字符、约4KiB JSON字节预算，配置/请求/响应均有上限；共享并发2，PG操作5秒查询超时。每用户最多50个活动草稿/200次运行回执，每租户200个发布版本；超过限制明确拒绝，不偷偷删除记录。

本次没有自动运行、分布式持久调度、条件分支、失败重试、修复执行或 AI 协助。AI 后续只产出待审阅的定义补丁，复用相同校验和预览门禁；诊断编排仍由 Rust 负责。未来如集成 Dify，只能作为受控外部诊断适配，需独立授权、预算与数据出域决策，不能替代平台实体/来源/权限边界。

## 取舍

单链可覆盖首批确定性清洗并便于逐条审计；不是 Dify 的完整功能复制。没有持久执行引擎，因此进程中断会丢失尚未保存的执行，不提供恢复/自动重试。实例写入完成后，需另行实现显式绑定和启用接入，再声明采集闭环。验证记录见 VALIDATION-REPORT §70。
