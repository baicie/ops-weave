# ADR-035：Host 库存扫描的来源租约与 fencing

状态：已实现；本机实际检查见 [VALIDATION-REPORT §41](../VALIDATION-REPORT.md)。

## 背景

单个 Host 扫描原本在完整分页结束后将未出现的 Host 标为 INACTIVE。实体锁和观察时间只能保护单条更新，不能阻止较旧扫描晚于新扫描完成后执行过时的缺失对账。并发 HTTP、多个平台进程或进程暂停恢复都能触发这一竞态，后续持续来源接入也依赖此边界。

## 决定

在现有 inventory PostgreSQL schema 增加 V020 `source_scan_lease`，每个可信 `(tenant, sourceInstanceId, externalType)` 保存一行。当前生产调用仅用于 Host。租约绑定内部 SyncRun UUID 和单调递增 fence，30秒有效，可续租，但开始后5分钟为不可延长的绝对截止。过期接管必须使用新 run 和更大的 fence，原 run 不恢复。计数到达安全整数上限失败关闭，禁止回绕。内存实现仅用于明确标记的单进程 fixture。

来源锁在短事务中获取，固定顺序为来源→实体→观测。PG 获取锁后读取数据库 `clock_timestamp()`，不信任客户端或应用进程时钟。HTTP fetch 不持有数据库连接；每次 fetch 前后及记录处理前续租。上游调用本身仍服从既有 HTTP 超时，不引入后台续租或隐藏重试。

库存 upsert 和最终缺失对账必须携带租约；验证、写入与续租/完成在同一事务和来源锁内进行。所有阻塞写完成后再次验证，过期或线程中断则整个事务回滚；多实体对账循环也逐项检查时间。最终对账和释放同事务提交。旧持有者不能写入、对账或释放新持有者。内部独立写入/对账入口遇到未释放扫描（即使已过期）也拒绝，避免绕过 fencing。

默认接口方法失败关闭，未实现租约的适配器不能悄悄继续非受保护同步。没有新服务、数据库、框架领域依赖或模型 Tool；HTTP 请求不能指定租户、来源、run、租约或 fence。失败响应仅含稳定错误码、固定摘要、计数与原 SyncRun ID。

## 故障语义与边界

- BUSY 不调用连接器；LOST/DEADLINE 不允许该扫描继续写库存或执行对账。异常时 best-effort 释放仅匹配本人的 token；数据库故障导致释放失败时等待过期接管。
- 已提交的部分记录和 Raw 不回滚成一个全局快照。租约解决并发写入次序，不能修复上游 offset 分页期间的数据移动；完成仍为 `offset-scan-attempt`。
- SyncRun 状态记录与库存完成事务分开。最后的状态写失败可能发生在对账已提交之后，所以 CHECKPOINT_FAILED 明确提示已提交库存变化可能保留，不能宣称一定没有对账。
- 进程中止可能留下 RUNNING 元数据；租约过期后新的显式扫描可接管，但不自动续跑旧 run、不自动修复其状态。失败/未知结果不能作为自动重试指令。
- 一行来源记录持续保留以保存 fence，不提供删除/清零接口。迁移需停旧版本写进程，不能让不识别租约的旧版本并行写库；生产迁移/HA/故障切换尚未验收。
- Item/Problem/History 是各自入口和边界；本 ADR 不声称其全部受 Host 租约保护。History 原有自身租约不变。通用 Resolver、持续多来源 presence、已有实体合并、来源调度和总存储配额继续未完成。
