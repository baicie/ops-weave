# ADR-078：固定接入的资产批次与扫描恢复

日期：2026-10-04。状态：已实施有界资产扫描；持续遥测与生产高可用继续验收。

固定接入配置此前只能即时预览，原运行器只消费旧采集链路的完整批次。预览截断不能作为完整扫描，来源变化后重新读取也不能代替失败批次的原输入。

继续使用 Java 应用服务、现有 PostgreSQL 和四个启动单元。WorkflowHostRuntimeService 负责固定 ZABBIX_HOST 来源与 ENTITY 目标，既有运行服务保留旧批次和手工执行路径。每页最多5条，清单最多1000项；连接、凭据、模型与算子版本不自动替换。

V043 在低频资产链路保存私有恢复输入：名称、地址、生命周期和规范资产标识。保留原批次UUID、读取时间、工作流摘要及前后游标。不是指标点存储，也不保存上游原始响应、凭据或会话；HTTP仅返回闭合元数据，行数据与清单游标不进入公开响应或普通日志。每个所有者最多200批，查询最多20条；到容量上限停止，不自动淘汰未确认记录。

来源网络读取在日志事务外进行，受理时再次核对代数、固定配置及当前授权。READY先提交，IN_FLIGHT再提交，随后完成资产写入和批次确认。只有全部可接受输出确认才推进私有来源游标；被流程过滤的输入仍计入已处理来源记录。健康空扫描可以完成但不删除资产，上游失败与清单变化不能伪装为空完整结果。

已调用输出后发生错误或受理后中断时保留UNKNOWN。遗留IN_FLIGHT等待60秒后转UNKNOWN并停任务，不自动重发输出。显式RESUME沿用原批次数据、时间、编号和已确认标识，重新签发有期限、有额度的可信授权；资产适配器按不可变Observation标识处理同内容重放，内容不同拒绝。STOP增加任务代数并保留checkpoint；新START不能丢弃未完成扫描。完成的旧版本允许显式启动已发布的新版本。

启动、停止和恢复沿用不可变命令回执，相同请求重放不重签授权或改变代数。公开授权不替代可信主体；执行、每条写入和最终确认重新检查范围和额度。历史读取核对固定来源权限，返回的批次资产标识也检查实体读取范围。历史可读不代表旧凭据仍可执行。

当前资产写入与停止通过现有租户事务锁串行，证明范围是本机单执行器及有界失败恢复。不是跨系统事务，也未验收连接丢失时的分布式租约/fencing、全局副本预算、生产调度、自动放弃原扫描或保留期清理。扫描有限并在完成后停止，持续指标/日志窗口、周期调度与S5整体继续。见[契约](../../contracts/workflow-host-scans.md)、[操作](../runbooks/workflow-host-scans.md)与验证报告§116。
