# ADR-100 关系实例维护闭环：终止、历史与并发基数

状态：已实施（2026-10-09，OW-ST05 增量一）

## 背景

第5节要求关系实例可人工创建、更正、终止并保留历史，类型方向、两端类型及基数在事务中检查，终止设置有效结束时间且不删除记录。此前只有"创建 + 活动关系分页"闭环（ADR-058、第146节），终止、历史与基数未实现；契约中也没有对应 Schema。

## 决策

1. **终止即写有效结束时间**：`POST /api/v1/entities/{entityId}/relations/{relationId}/close` 写入 `validTo` 与人工理由（1–256 无控制字符），关系行不删除。理由是人工断言依据，只在历史中返回；创建回执与活动页不返回理由，`sourceRef` 继续只留服务端（沿用第146节决定）。
2. **独立幂等键**：关闭使用自己的 `requestId`（`close_request_id` 列，唯一索引）。同键同内容重放返回原回执；同键异内容 409；新键终止已终止关系 409；关系不存在 404。创建幂等键（等于实例 ID）不受影响。
3. **对象版本 CAS**：`entity_relation` 增加 `version` 列（V063），创建为 1，终止时 +1。终止命令携带 `expectedVersion`，在写事务内比对；不匹配 409。服务层先 `find` 做双端 `entity.manage` 授权与时间窗校验，事务内重放/状态/版本判断由存储层负责，避免重放被"已终止"预判误拒。
4. **基数在写事务内检查**：按已发布关系模型版本的 `cardinality`（ONE_TO_ONE / ONE_TO_MANY / MANY_TO_MANY）解析出每端活动上限（0 为不限），由存储在写事务内计数判定，计数对象是 `valid_to IS NULL` 的未终止关系（设置预定结束时间的区间关系不占基数，属文档化边界）。PostgreSQL 先锁定双端实体行再计数，同端点并发写入被串行化；内存实现以单锁等价。终止释放基数名额。未知基数字符串按 409 失败关闭。
5. **历史只读分页**：`GET .../relations/history` 返回活动与已终止关系（含 `closeReason`），按关系 id 游标分页、双端可见性过滤、与活动页相同的 1000 候选扫描预算（耗尽 503），游标只锚定可见行。列表不删除、不聚合。
6. **与拓扑一致**：拓扑读取与活动页同表同 asOf 语义，终止后的关系自动退出"当前"视图；详情/列表/图共用同一投影，不另建缓存。

## 后果与边界

- 已覆盖：人工终止闭环、历史追溯、并发基数、越权端点拒绝、未知结果保留原请求并显式原样重试（前端）。
- 未覆盖（不宣称已交付）：来源关系输出（工作流写关系实例）、端点待解析状态、来源与人工冲突的可见策略实现、关系"更正"（改端点/类型）、拓扑多层展开的完整依赖图。这些继续按第5节与 OW-ST05/06 验收。
- 基数只约束未终止关系；跨模型版本的关系实例按 `relation_type` 归组计数。
- 契约：`entity-relation-close-command`、`entity-relation-history-entry/page` 为闭合 Schema；成功回执复用 `entity-relation-receipt`。
- 存储：V063 增列 `close_request_id`/`close_reason`/`version` 与检查约束（理由必须伴随结束时间）；PostgreSQL 分页/历史按游标是否为空使用两条确定 SQL，避免 NULL 参数类型不可推断（本轮在真实 PostgreSQL 上首次实跑暴露并修复）。
