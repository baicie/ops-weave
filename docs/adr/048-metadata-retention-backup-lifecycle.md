# ADR-048：元数据留存与备份生命周期（设计边界）

状态：**设计边界，不是已交付能力**。本文只记录当前每类数据实际保留什么、什么已经被有界化、什么仍然开放，以及
后续要在什么前置条件下才能做备份/擦除。不是备份手册，也不声称任何恢复演练已通过。实现状态见
[IMPLEMENTATION-STATUS](../IMPLEMENTATION-STATUS.md)，实际检查见 [验证报告](../VALIDATION-REPORT.md)。

## 问题

平台对“内容”已经有明确的留存语义，但对“元数据”没有：

- AI 正文与读取审计有可信租户策略、预览/确认、PG 原子清理（ADR-034、V019）；
- 连接自检回执按 tenant/source 保留最近 100 份（ADR-045、V026）；
- 扫描运行记录现在有范围/租户预算（ADR-047、V027 语义在应用层，无新列）；
- 但资产观测、快照、审核回执、更正回执、告警规范化历史、Incident 时间线、费用账本、证据与读取审计、
  幂等回执、绑定与登记记录，都只有**单次读取上限**，没有时间窗口、总量配额或清理入口；
- 没有任何备份、恢复或物理擦除验收：PostgreSQL 的 WAL、快照与磁盘副本不在应用控制范围内。

把这些混为一谈会得出错误结论：清掉 AI 正文**不等于**删除了该次诊断的授权元数据、费用和引用；同样，
“按 tenant/source 保留 100 份回执”也不等于这张表有总量上限。

## 决定（边界与顺序）

1. **留存是分类的，不是全局一刀切。** 三类数据必须分开处理，且不能互相代替：
   - **内容**（模型提问/摘要/正文）：可按租户策略清理，保留授权元数据（ADR-034）。
   - **业务记录**（资产、观测、绑定、Incident、指标绑定、流水线版本）：清理会改变业务事实，必须先有
     明确的审计与恢复语义，本轮不做自动清理。
   - **授权与账本**（Principal 相关回执、费用、证据引用、幂等键）：是“谁在何时被允许做了什么”的唯一
     证据，不能因为清理内容而一并删除。
2. **有界化优先于删除。** 对只追加的运行/回执类表，先用范围或租户预算把增长变成有界（ADR-047 的
   `source_sync_run`、ADR-045 的回执即此模式），而不是引入后台删除任务。业务记录类表不套用该模式。
3. **清理必须是显式动作。** 需要有预览 → 人工确认 → 原样回执 → 未知结果可查询的同一形状（复用
   ADR-034 的模式），不接受隐藏的定时删除。
4. **备份/恢复是独立议题。** 在提供任何备份或恢复承诺之前，必须先有：明确的 RPO/RTO 目标、数据库级
   备份方式（含 WAL 与保留窗口）、恢复演练记录、以及“恢复后 ID/幂等键仍然成立”的验证。当前**没有**
   这些材料，因此不提供任何备份承诺，也不写生产 Chart。
5. **物理擦除不承诺。** 应用层删除只保证逻辑上不再可读；WAL、副本、文件系统快照与磁盘残留不在本平台
   控制范围内，需要独立的存储层流程与验证。

## 当前每类数据的实际边界

## 已实现的第一小步：收据容量可见（第57节）

| 数据 | 当前有界方式 | 仍然开放 |
|---|---|---|
| 扫描运行记录 `integration.source_sync_run` | 范围 1000 行 / 租户 5000 行预算，打开扫描时清理（ADR-047） | 无后台清理、无跨租户治理、遗留 `RUNNING` 回收 |
| 来源连接自检回执 | 每 tenant/source 最近 100 份（ADR-045） | 跨来源汇总、总量配额 |
| AI 正文与读取审计 | 可信租户策略 + 预览/确认 + 原子清理（ADR-034） | 其他业务数据、会话/标记/费用元数据 TTL |
| 来源快照与绑定更正回执 | 每 tenant/source 最多 1000 份，**达到上限即拒绝写入**（fail closed）；`GET /api/v1/integrations/cmdb/receipt-capacity` 只读报告计数、上限与 `OK/NEAR_LIMIT/AT_LIMIT`（80% 起告警），让上限在写入被拒之前可见 | 清理入口、扩容路径、跨来源汇总、后台调度；容量视图不删除任何回执 |
| 资产观测 / 快照 / 审核与更正回执（清理侧） | 只有单次读取上限 | 时间窗口、总量配额、清理入口 |
| 告警规范化历史 / Incident 时间线 | 快照上限（50 问题 / 100 时间线点），无分页 | 时间线分页、留存总量 |
| 费用账本与证据引用 | 单次查询上限；账本保留原费率与用量 | 核销、聚合、时间清理 |
| 备份 / 恢复 / 物理擦除 | **无** | 全部：RPO/RTO、WAL 保留、恢复演练、擦除验证 |

**为什么只做可见而不是自动清理**：删除回执会让旧请求的幂等结果不可再查（ADR-037 的回执是"原请求原样取回"的唯一依据），
所以清理必须是显式的人工动作，而不是后台任务。容量视图先让"何时会写不进去"可见，清理入口仍待设计。
资产观测不进入清理候选：已存储的工具证据引用观测 id，删除观测会留下悬空引用。

## 后果

- 运维不能用“已清理内容”推断数据已删除，也不能用“回执有上限”推断整表有上限；本文列出每一项的真实
  边界，避免把局部有界当成全局治理。
- 在提供备份承诺之前，试点交付（M7）不能宣称具备恢复能力；这是 M7 的退出条件，而不是本 ADR 的交付。
- 后续任何清理入口都必须先补契约、领域规则、审计与负例，且不得删除授权/账本类记录。
