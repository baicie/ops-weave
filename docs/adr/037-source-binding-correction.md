# ADR-037：以新观测更正当前来源绑定并保留历史归属

状态：实现与实际验证见 [验证报告第43节](../VALIDATION-REPORT.md)。

## 问题与决定

ADR-036禁止快照隐式重绑，但操作员录错外部对象/登记pin后没有可审计的纠正入口。增加固定CMDB导入来源的人工绑定更正，不增加服务、数据源、模型工具或实体合并。

更正必须同时提交：原来源外部ID、最后确认的snapshotId、原/目标实体ID及版本、当前已核对目标UUID pin、一份更新的来源观测和原因。服务端 tenant/source/namespace/actor来自可信边界；调用者需 tenant-wide entity.read/entity.manage/source.sync。新观测仍受固定映射摘要、过去7天、严格晚于该来源已保存快照的限制；不允许只把旧观测换个entityId后声称新目标已被确认。

页面通过受权配置、实体、登记解析和来源状态读取呈现预览，编辑会使确认失效。预览是有版本的多个读取，并非数据库一致快照或长期执行许可；提交在服务端重新检查。只有显式人工确认才发一次写请求，未知结果保持原ID查询，不自动重试。刷新只保留请求ID，不保存凭据、JSON或审批状态。

## 事务与历史

复用来源锁，按UUID顺序锁原/目标实体，再锁外部对象绑定；原snapshotId、双方版本、目标登记及作用域逐一复核。相同实体换成新的登记pin允许，同实体同pin的无变化操作拒绝。若原绑定仍有生效字段，必须先人工撤销；不自动转移字段权威。

单个PG事务仅替换当前presence投影，再经相同快照写入器导入一条新观测与PENDING字段，更新双方生命周期/版本，并保存V022更正回执。来源确认在事务内部暂时移除，但原值完整保存在同事务不可变回执；任何冲突、超时或后续失败都会回滚，外部看不到中间空状态。同一实体只增加一次版本，两个实体各增加一次；更正不是一次完整快照，不对其他对象标缺失。

原Observation、快照、字段审核、Zabbix ExternalLink、MetricBinding、Incident/Evidence引用不移动或删除；旧待审记录保留但旧版本不能再被接受。它们记录当时的归属，不能被读成更正后的当前绑定。原资产不再受该来源保护，目标资产依据这份新鲜观测获得来源确认；已有其他有效来源仍按原规则保留。

请求ID也用于新快照；若ID已用于普通快照而没有更正回执，拒绝整笔更正。相同tenant/source/namespace/actor/原输入/摘要返回原回执，改输入或主体冲突。GET回执限原操作者；整源管理者可在原/目标资产的有界历史页看到当时操作者和原因。历史按UUID分页，不保证跨页快照。

## 边界

请求最多16KiB，每tenant/source最多1000个更正回执，且仍消耗现有1000份快照预算；每页最多25条（Web10条）。来源锁等待/SQL超时复用现有边界，事务完成前复查30秒截止。没有自动清理、隐藏重试或失败空快照。相同来源外部ID仍唯一；目标已有另一个外部对象绑定会冲突，不能借更正绕过上限或覆盖第三方绑定。

这是当前补充来源绑定及登记pin的更正，不是已有Entity合并/alias、主Zabbix ID迁移、命名空间迁移或对历史诊断的重计算。未连接厂商API、未后台轮询；手工来源完整性/登记准确性仍需操作员核对。迁移必须停止旧writer，生产滚动升级/HA/容量与真实来源/模型/IdP验收仍未完成。
