# ADR-050：Raw 写入容量准入，保留原引用

日期：2026-09-27。范围：M2 的 Raw 有界保留；不增加服务、后台清理或动作工具。

## 问题

PostgreSQL Raw 只有单次读取上限，没有写入容量边界。内存 fixture 虽限制为1000条，却通过全局逐出旧记录腾空，
可能让其它租户或已有 Observation/Replay 的 Raw 引用失效。读取上限不能证明保留容量有界。

## 决策

- 同一 tenant/source 最多1000条 Raw，同一 tenant 合计最多5000条。Host 和 Item 共用来源额度，
  不因新 runId 重置；不同来源共享租户额度，不同租户分别计数。
- 单条已序列化 UTF-8 JSON 以及 PostgreSQL JSONB 规范化文本各不超过65536字节。
  PG 必须在两次大小检查都通过后插入，避免刚写入的记录立即被读取上限拒绝。
- 达到数量或大小上限即拒绝新写入。**不逐出、不删除、不改写已有 Raw**；失败不触发缺失对账。
  已提交的页/Observation/Raw 保留，扫描以既有 `RAW_PERSIST_FAILED` 失败，退休数为0且不声明完整快照。
- PG 在同一事务内取得租户级 advisory lock、检查来源/租户计数并插入；不同连接不能重复消费同一额度。
  计数最多读到租户上限条数，沿用现有 `(tenant_id, source_instance_id, sync_run_id, id)` 索引；锁/查询5秒超时。
  这是资产/接入元数据路径，不把高吞吐指标采样点存入PG或逐点检查PG。
- 内存 adapter 仍明确非生产：同步准入、保留既有记录；用保守字符界估计JSON大小，会比PG更早拒绝部分大对象。
  不把该近似估算当作真实来源验收。读取上限统一为端口的100条。

发布上限定义在 `RawRetention`；较小策略只允许收紧。当前没有运行时扩容、租户配置接口或用户可提交的配额字段。
契约不增加新的HTTP形状，容量/大小失败沿用既有失败码；该码也可能表示其它持久化失败，不能只凭它认定容量已满。

## 旧数据与边界

旧库超过上限时保留原数据，并拒绝后续写入；这不是自动迁移清理或旧数据总量达标的证明。
旧超大payload读取时继续返回显式不可读取的Raw项，Preview/Replay保留缺失/超限语义，不造空对象。
数据库表本身没有给管理员直接SQL加配额；准入约束的是平台Raw执行端口，生产部署仍需限制数据库角色权限。

容量耗尽后不能靠重复扫描恢复，也没有自动重试或清理。需要后续有审计、引用完整性和恢复语义的显式治理设计，
不得直接删除被Observation/Replay引用的记录。备份/WAL/磁盘物理字节与受保护扫描记录的总量不在此承诺内。

验证结果见 [VALIDATION-REPORT 第59节](../VALIDATION-REPORT.md)；编写测试不等于测试通过。
