# ADR-049：被拒写尝试的审计留存

状态：实现与实际验证见 [验证报告第56节](../VALIDATION-REPORT.md)。

## 问题与决定

补充来源链已经有两类"人工写"的完整回执（ADR-027 字段审核、ADR-037 绑定更正），但回执只在
**成功**时产生：一次被拒的请求（实体/审核版本已变、绑定被占用、字段仍生效、请求标识冲突、达到留存上限）
只返回 409 与一个稳定错误码，没有任何持久痕迹。结果是"谁在什么时候试图改什么、为什么被拒"事后无法回答，
而这类拒绝恰恰是运维最需要看到的信号（重复冲突 = 有人在用过期的页面，或者上游在并发改动）。

决定：为**被拒的**补充来源写操作增加一张有界审计表 `integration.rejected_write_attempt`（V027），由两个
存储装饰器在同一个调用点记录——字段审核（`stage`/`decide`）与绑定更正（`correct`/`ingest`），覆盖内存与
PostgreSQL 两条路径。

记录内容被刻意收窄：稳定的 `reasonCode`、被拒的操作（白名单标签）、actor、**尝试过的字段名**、时间与
tenant/source。**不记录字段值、厂商报文、异常消息**——拒绝日志不能变成存放不可信来源文本的地方。

## 语义与不变量

- **拒绝不改写原请求**：装饰器记录后原样重新抛出同一个异常。审计是拒绝的证据，不是第二道闸门，也不是隐藏重试。
- **只记录拒绝**：成功路径不写审计（成功已有回执），读取路径不写。
- **字段名白名单**：只记录领域认识的 `name/ip/owner/environment`，其余名字一律丢弃而不是照抄；最多 16 个。
- **actor 不可回显坏输入**：不可用的 actor（空白、超长、首尾空格）记为固定值 `unknown`，不把请求原文写进日志。
- **只记录可读的来源**：读取入口只服务配置中的导入来源，因此装饰器只写该来源的记录——写一条谁也读不回来的
  记录比不写更糟。
- **有界**：每 tenant/source 保留最近 500 条（`OPSWEAVE_REJECTED_WRITE_MAX_PER_SOURCE`，只能收紧），在
  写入的同一事务里清理更旧的记录，与 ADR-045/047 的追加型表同一模式。
- **读取不重放**：`GET /api/v1/integrations/cmdb/rejected-writes` 只读；它不重试、不授权、不返回字段值。

## 授权

读取沿用写入所需的同一组权限：`entity.read` + `entity.manage` + 源级 `source.sync`，并要求这些权限对配置的
导入来源成立。只有 `source.sync` 会被 403；未配置来源返回 503；未认证返回 401。

## 边界

本轮**不做**：审计的 Web 页面（接口与契约已就绪，页面留作后续）、按时间窗口的清理入口、跨来源汇总、导出、
以及"拒绝次数"告警。审计也不改变任何业务语义：被拒的请求仍然被拒，绑定与字段状态不因记录而变化。
`source_sync_run` 之外的其他业务/授权元数据生命周期仍见 [ADR-048](048-metadata-retention-backup-lifecycle.md)。
真实 Zabbix、真实模型、真实 IdP/TLS 与人工抽样审阅仍未验收。
