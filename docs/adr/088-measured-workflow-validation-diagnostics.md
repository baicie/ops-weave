# ADR-088：保存实际检查过的工作流统计

状态：已接受，当前有界单执行器阶段。

原输出批次证明只能描述通过准入后的输入和写入确认，不能解释准入前的字段拒绝。连续处理在第一组错误后停止，不能把后续未执行记录计算为通过或拒绝，也不能根据通用错误码猜测来源返回数量。

既有Java纯领域累加器记录同一次转换评估的行处置和节点结果。执行器以已有固定计划处理每组最多5条；第一组错误后保留剩余unknown。来源未返回列表的失败只有闭合错误代码和不可用数量。类别按拒绝记录去重，节点问题按每节点每记录去重；指标/日志窗口上限仍为600/1000。没有第二遍评估、逐点PG查询、原文存储或隐藏执行服务。

V049在既有PG保存不可变检查元数据，按租户/本人最多200条；单次来源/转换尝试最多一条，来源IO前和追加前重查当前代数、身份、固定版本与容量。停止或撤销使过时代数的追加失效。新表不承担输出状态、授权、checkpoint或业务原文。失败记录只重抛原有闭合执行失败；元数据追加失败不尝试再次追加成功或虚构失败证明。

只读服务固定当前可信身份、发布摘要和目标读取权限，先过滤版本再限制21条；报告返回20条，原UUID查询更早记录。私有实体见证不能投影到公开响应。无来源/输出/动作依赖。前端请求容器持有取消和会话，展示组件只接收数据；未记录字段显示“—”，部分处置不会呈现整批成功率。

同时修正指标补采查找：原确认窗口由专用租户/本人/版本/摘要/截止时间查询确定，与最近20条展示列表分开；同窗口优先最完整的确认证明。21条后来失败证明挤出原记录后仍可补采，旧证明和checkpoint规则保持。

实际覆盖包含纯领域、真实PG重开/事务/隔离/损坏/容量、隔离Schema前迁移→回滚→重建、真实时序库补采、HTTP边界，以及本机来源的直接拒绝和节点拒绝两条Synthetic Fixture链路。详见[验证报告§126](../VALIDATION-REPORT.md)和[契约](../../contracts/workflow-diagnostics.md)。保留、容量治理、主机细分、queueWait、阈值告警、历史修订及分布式租约/fencing继续，未增加数据库或启动单元。
