# ADR-092：保留旧日志结果的不确定性

状态：已实现，实际验证结果见验证报告第130节。

旧执行器曾把写入成功后的回读失败记录为 FAILED/OUTPUT_REJECTED。原批次体因此不能证明未发生写入。V052 的 rejection_known 默认 false，只有修正后的执行器能为写入前的明确拒绝保存该证据。迁移不改旧批次体，不删除日志，也不把存在输出等同完整确认。

质量观察把缺少该证据的日志 FAILED 投影为 UNKNOWN/OUTPUT_UNCONFIRMED。预期记录数计入 unknown，confirmed 和 outputRejected 均为0；UUID、窗口、计数和观察时间沿用原证明。关联的失败任务在质量报告中显示 OUTPUT_UNCONFIRMED。投影只读取既有批次与证据，不连接来源或日志库，不修改原记录。

持续日志按版本状态仍返回原批次体，另带闭合、有界的 uncertainBatchIds。列表最多20个UUID，只能引用本响应内的 FAILED 批次。前端显示结果待确认，不提供原结果不支持的核验操作。任务关联这些批次时，服务器的 resumeAllowed=false；START/RESUME 不能据原 FAILED 重写输出。原日志仍可按既有授权分页查看，完整回读只表示当前读取事实，不改变原证明。

当前可信身份可在运行质量中明确终止恢复，复用既有八字段命令、十二字段回执及 V050 事务。仅当前 FAILED/STOPPED 任务的原 pendingBatchId、固定版本、代数和权限全部匹配时受理；写入前已有明确拒绝证据的批次不适用。任务转为 ABANDONED、增加一代并撤去后台授权，原游标、确认数量、原批次体及证据保持。原UUID查询和相同内容重放重新校验原父对象，返回不可变回执。容量、时钟、本人/租户和对象范围门禁保持。

终止后可明确 START 更高发布版本，旧终止事件与未知质量观察保持；同版本不能重启或核验。新版本读取自己的新窗口，可能与旧未确认输出有时间重叠，不承诺跨版本去重或填补空档。没有增加迁移、数据库、启动单元或后台补偿执行器。单次样本、生产租约/fencing、保留和生产认证继续按路线图推进。

API 与 Web 应同步更新。旧版本状态响应不带新增观察字段，原控制回执和存储批次 Schema 不变。回滚应用时须保留 V050/V051/V052 及已受理的终止状态，禁止启动会把旧 FAILED 当作安全重写依据的执行器。参见[质量协议](../../contracts/workflow-quality.md)、[恢复协议](../../contracts/workflow-recovery.md)及[使用说明](../runbooks/workflow-recovery.md)。
