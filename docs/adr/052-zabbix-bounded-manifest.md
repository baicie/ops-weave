# ADR-052：Zabbix 有界成员清单与单 Worker 多流

- 日期：2026-09-27
- 状态：已采纳；本地 Zabbix7.0.27 证据见验证报告§64
- 范围：M2/M3 接入正确性，不增加启动单元、数据库或模型工具

## 原因

真实 Zabbix 忽略 host.get/item.get 的 offset；此前协议桩模拟了不存在的能力。最高 ID 与总数也不能检测等量成员替换。
实际三项指标需要同一 Worker 采集，且已存检查点的 streamName 与 initialFrom 不能因重启或扩展采集项而改变。

## 决策

采用[扫描契约](../../contracts/host-scan.md)中的有界成员清单：最多1000个对象，固定 SHA-256/计数/本地位置，每页重验成员，按显式 ID 批量取详情，最后再次验证，任何不一致均不能触发缺失对账。
保留历史 wire 标签，不重写既有记录、不把旧标签追认为新验证。1000上限独立于 Raw 已占额度；容量超限明确失败。

Worker 接受可信配置 OPSWEAVE_HISTORY_STREAMS，最多8条串行数据流。每项为 itemId:streamName[:initialFrom]，可分别固定已存在的检查点起点；省略起点时使用全局 INITIAL_FROM。不与单项 ITEM_ID 同时配置。
沿用每流最多8页、单窗口加重叠不超过3600秒、HTTP超时与检查点 lease/fence；一轮最多64次来源分页，并发为1。失败只影响本流且不推进进度，其余流继续；没有轮内重试或隐藏 fallback。
单流原配置兼容。名称、起点、来源、series fingerprint 仍须与检查点一致；不清除或篡改旧检查点来绕过约束。

内存可用比例按0.01归一化为 unit=1 的 gauge；系统 uptime 为秒数 gauge，重启后可下降，不能当 counter 计算速率。
新映射使用独立1.0.0文档；不修改已发布 Skill。

## 局限

有界 ID 清单每页会重读一次，适用于当前小规模 MVP，不代表大规模性能验收。成员稳定不等于字段的事务一致性，快速改变后恢复的成员无法承诺检测。
多流按序轮询，慢来源会延后其他流；仍有显式超时与有界总数，不承诺公平调度或分布式采集。
