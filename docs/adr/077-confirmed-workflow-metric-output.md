# ADR-077：固定指标工作流的有界样本输出与确认

状态：已实现本机固定样本输出；持续采集与生产恢复未完成。日期：2026-10-04。

## 问题

标准指标工作流已有固定连接、指标项、映射和不可变版本，但测试运行只返回转换结果。外部时序库的 HTTP 受理不能证明整个批次已落库；响应丢失也不能按新标识重写。需要实际输出、原请求恢复及精确点回读，同时保留缺失和未知状态。

## 决策

沿用 Java 平台、已有 PostgreSQL 和 VictoriaMetrics。纯 Java 应用服务管理一次最多5点的命令，平台适配器负责固定 loopback 协议。没有增加启动单元、数据库、执行框架或动态代码。

写入须引用当前授权下的已发布工作流和15分钟内服务器产生的 RUN 回执。原始样本必须与该回执的配置输入摘要相同；执行器重新编译固定算子和标准映射，核对来源、映射、时间和精度，转换一次。接入配置与来源元数据在受理及外部尝试前复核；请求不能提供身份、权限、目标地址或自定义标签。

系列使用可信 tenant、owner 摘要、接入/指标项/来源主机、完整指标键、映射/配置/工作流固定版本摘要和固定维度。采用独立 `opsweave_workflow_metric_value` 名称，保留既有资产指标语义。来源主机标识不是平台资产标识；当前没有凭空建立 MetricBinding 或资产关联。请求 UUID 不进入系列标签。

V042 在已有 PG 事务中先保存 PENDING 元数据：原命令摘要、原 RUN、系列标签/摘要、归一化批次摘要、最多5个时间戳和数量。数值及原始样本不进入此表。相同 UUID/内容只返回原记录，不访问来源或写入库；不同内容409。每 owner 最多200份记录、并发2，查询最近20份并明确截断；清理和分页尚未实现。

适配器先核对固定存储精度及已有点，已有相同值可直接确认，已有冲突值在 POST 前拒绝。缺失点只发一次非流式 Influx POST；随后一次精确标签、时间和值回读。204、解析失败、响应丢失或部分可见均不能确认全批。POST 尝试后的不确定结果统一 UNKNOWN；全批 unknown 数保守保留，confirmed 为0。没有隐式 POST 重试或可见性轮询。

原回执 GET 只读元数据；显式 verification GET 只查询时序库并细化元数据。全批摘要匹配才变为 CONFIRMED，缺失/错误值/查询失败保持 UNKNOWN。FAILED 表示已确定在业务 POST 之前拒绝。命令/批次字段不可变，状态只允许 PENDING→UNKNOWN/FAILED/CONFIRMED、UNKNOWN→UNKNOWN/CONFIRMED；终态不能改写，未知不能被一次失败查询降为失败。元数据受理和外部写入不是跨系统原子事务，不宣称 exactly-once。

## 交互与恢复

已发布固定指标页面提供折叠的输出面板。写入前受控读取原值，原 UUID/命令在 POST 前保留于页面内存；结果不明时锁定版本/输入和关闭，不自动重发。用户可查询原回执、验证批次及回读点。只有显式原 GET 404 且仍保有原命令时允许重发相同内容；放弃确认不会取消服务器写入。页面重载通过最近记录恢复 UNKNOWN，但没有原样本时不能重发。身份变化/403清除私有状态并丢弃迟到响应。

展示组件只接收数据和回调；请求、身份和门禁归页面，客户端复核闭合契约、系列摘要、原命令和匹配点的批次摘要。缺失点显示实际数量与“尚未完整匹配”，不伪装完整空数据。

## 未完成范围

此入口处理当前样本，不是连续完整窗口，不推进采集 checkpoint。固定配置后台批次、失败重放/管理恢复、日志持久输出、真实资产关联、租约/fencing、生产身份、容量及保留策略继续。只在本机可信配置启用 PG/时序端口，不把 available 当健康或生产认证证明。
