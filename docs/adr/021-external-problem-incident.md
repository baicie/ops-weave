# ADR-021：外部问题与 Incident 的原子持久化

状态：接受，2026-09-25。承接 ADR-020，只实现本机可验证的 M3 切片；真实 Zabbix 及 M4 模型链尚未验收。

## 决策

显式 `POST /api/v1/integrations/zabbix/problems/ingest` 导入一个有界页面（最多 100 条、窗口最多 24 小时）。使用可信 Principal 的 tenant 和配置来源，复用 `source.sync` 授权的来源读取；请求只含 from/till/afterEventId/limit。上游失败不启动写事务，空页不删除问题或关闭 Incident。每实例最多两个同时导入，不隐藏重试或触发通知、修复、诊断。

一次发生由 tenant/source/problem event ID 唯一标识；初始 Incident ID 由这三个字段确定，不能用 trigger ID 聚合重复故障。PostgreSQL V010 在一个事务里保存 Incident 快照、来源发生索引与实体范围字段。导入整页成功或整页回滚；按确定的 Incident ID 顺序加行锁，并在锁内合并，避免并发新建和乱序恢复回退。SQL 3 秒、锁等待 2 秒、导入循环 10 秒截止，连接池等待 5 秒；不是分布式配额或 HA 保证。

保留最新规范化问题观测、fixture/JSON-RPC 来源模式、适配契约版本、首次/最近接收时间和问题/恢复时间线事实。来源时间保留纳秒；发生时间与本平台可见时间不同。重复接收不重复追加事实，只有观测新鲜度改变时不增加人工并发版本。已知恢复不得回退；同一发生更换来源模式或已有 Host 绑定冲突时拒绝。当前不是每次原始响应的完整归档，不能回放任意历史 asOf。

实体仅通过同租户、同来源、external_type=host、generation=1 的 ExternalLink 解析，不能按名称/IP 猜测。缺失链接保留，后续 Host 同步后再次导入可补齐。已有历史链接保留，链接不因来源 Host 列表变化而静默替换。当前缺失 Host 数与“来源未返回任何 Host”的 gap 是不同信息。

## 人工状态与权限

新建 Incident 为 OPEN，即使导入时外部问题已经恢复。来源恢复不替人关闭 Incident；人工状态使用现有 OPEN/INVESTIGATING/MITIGATED/RESOLVED/CLOSED 转移图，RESOLVED 额外要求关联问题全部有明确恢复事实。请求含 expectedVersion/target/requestKey；变更和幂等记录同事务提交，同键只接受相同操作者、预期版本、目标，返回原始结果。冲突返回 409，存储不可用返回 503。

列表和详情要求 `incident.read`、`entity.read`。可信 Incident allow-list 与所有关联实体的范围约束在 SQL 的 LIMIT 之前执行；部分实体范围的用户看不到未映射或范围不完整的记录，租户级实体范围用户能看到显式缺口。跨租户/不可见数据不返回详情。人工变更还要求 `incident.manage`，并在事务内重新检查存储的关联范围；菜单状态不能替代授权。

默认配置没有新增权限；本地验收进程显式启用 incident.read/incident.manage，仍只绑定 loopback，随机 Token，固定该进程的开发租户。新能力不代表生产身份已经完成。

## 页面与限制

页面提供服务端状态筛选、25 条游标分页、详情、新授权资产读取、来源/缺口/时间线及显式人工流转。提交超时保留请求键以供显式重试；401/403 或身份变化清空旧数据，旧响应不能恢复缓存。链接只携带资产选择和一小时 UTC 窗口，指标页重新读取授权资产；Token 不放 URL。指标 Host 选择器改用有界分页，不再调用旧全量实体端点。

旧 GET `/entities` 标记 deprecated 并复用授权分页，最多读取 101 条用于判断是否超限：可见记录不超过 100 时保持旧 items 响应，超过时明确 422/PAGED_READ_REQUIRED，不静默截断。新 Web 消费者均使用 `/entities/page`。

快照最多 50 个问题、100 条时间线、100 个关联实体，编码最多 240000 UTF-8 字节；超限拒绝而不截断成完整结果。V010 是当前新建数据库路径，V001 仍为不可部署原型。未实现：人工合并/拆分及重定向后导入归属、时间线分页/留存、原始告警完整归档、历史实体快照、全局关联关闭、抑制驱动的自动诊断、真实来源验收、后台扫描、生产迁移/HA。后续合并/拆分必须先调整按初始 ID 查找的导入策略，避免重建已合并记录。

实际检查见 VALIDATION-REPORT 第 27 节。浏览器拦截 fixture 的用例与真实本机 PG/VM 验收分别记载，均不计为真实厂商验收。
