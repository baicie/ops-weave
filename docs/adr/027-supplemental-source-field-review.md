# ADR-027：补充来源字段的人工确认与撤销

日期：2026-09-25。状态：本机导入切片已验收；通用多来源治理与真实厂商接口未验收。

## 目标与约束

首个跨源治理路径是固定版本 CMDB 导入记录补充现有 Zabbix Host。CMDB 接口尚未提供，使用明确的导入契约，不宣称厂商 API 已连接。输入在受权人工页面提交，经固定 PipelineDefinition 映射、预览、确认后才能影响 Entity。原始输入和当时主来源投影不可变保留，决策记录可信 actor、原因、版本及幂等键。

Zabbix EntityId、ExternalLink、指标绑定和已保存 Incident/Evidence 引用保持稳定；补充来源在确认前不创建第二个可供遥测关联的资产。字段确认不搬移既有业务引用，不按名称或 IP 自动认定身份。同一补充来源外部对象不能同时绑定两个资产。

允许确认 name、ip、owner、environment 四个字段的主来源或补充来源选择，其他身份、采集模式、映射引用和监控状态不可由导入覆盖。当前配置是有版本的固定规则，不接受脚本、SQL、任意字段路径或 URL。数据只显示为文本。

## 生命周期

1. 创建待确认记录：绑定目标资产及其版本、补充来源外部身份、观察时间、原始输入和 PipelineVersion/digest。仅暂存，不改变资产。
2. 接受或拒绝：需当前目标的读取/管理权限和补充来源权限；接受时再次检查版本、字段和来源新鲜度。相同幂等键重复返回原回执，异内容拒绝。
3. 后续 Zabbix 更新仍保存原始主来源观测；已确认的字段选择参与当前投影，不能被普通同步覆盖。
4. 撤销当前生效的确认：恢复最新主来源字段，保留原始输入、补充观测与决策历史；不能借旧回执撤销更新的确认。

补充数据的观察/接收时间、过期状态及字段来源必须可查询。保留过期的最后已知字段时必须明确标记，不能当作新鲜观测；缺失字段不猜测补全。来源不完整或失败不得触发资产删除。

本次导入契约只有字段，不包含生命周期或实时 presence 断言。因此主来源完整扫描对账仍管理资产生命周期；补充字段不能把失联资产变成 ACTIVE。对账同时更新撤销所依据的主来源快照，撤销不复活 INACTIVE 资产。未来第二个持续采集来源的 presence 融合需另行实现。

每个资产最多一条生效确认，每个补充来源外部编号最多一个生效目标。切换记录前显式撤销旧确认，再基于当前资产版本重新暂存；不把旧确认静默替换。ACCEPT 必须在观察时间的七天有效期内，所有输入字段显式选择 PRIMARY 或 SUPPLEMENTAL。REJECT 不增加 Entity 版本，ACCEPT/REVOKE 增加一次；重复决策按原请求和 actor 返回原回执，即使其后已经撤销。

## 持久化与权限

使用现有平台 PostgreSQL，不增加启动单元或数据库。受权人工导入的原始记录作为来源确认记录的一部分保留，Raw 引用只指向该本地受控记录，不触发远程下载。事务同时保存生效绑定、字段投影和决策回执。开发内存适配实现同样的语义，并明确标注。

固定导入配置 `cmdb-host-import@1` 使用独立 `cmdb-host-import-v1` engine/digest；原 Zabbix PipelineVersion 的 engine/digest 不变。普通 Zabbix 发布/重放端点继续拒绝 CMDB profile。V015 保留导入记录、最新主来源快照与不可变回执，唯一索引约束生效绑定；与采集共用按租户/资产的事务锁，并对跨资产竞争同一来源对象加锁。补充记录不改写 Zabbix ExternalLink，接受时以独立 `cmdb-host` 身份写入不可变 Observation。

所有读取、暂存、决策和幂等重试都要求目标 `entity.read` + `entity.manage`，以及配置来源的 `source.sync`。来源 ID 由服务配置提供，actor/tenant 由可信 Principal 提供；请求不能带这些字段。默认不配置导入来源，也不向开发角色默认添加 `entity.manage`。这保持当前仅 loopback 的开发边界，不是生产登录。

这是一条受控平台元数据工作流，不是模型 Tool、远程执行动作或通用资产合并接口。跨 Zabbix 实例已有资产合并、自动强标识匹配以及完整来源生命周期仍需独立实现。验收状态以 IMPLEMENTATION-STATUS 和 VALIDATION-REPORT 为准。
