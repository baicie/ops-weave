# ADR-094：来源端口的实测读取诊断

状态：已接受。日期：2026-10-05。

记录转换统计的分母来自完整、有界的来源返回值。来源在返回之前失败时，没有可供转换的记录总数，不能将它补成零，也不能从 HTTP 请求次数推断失败记录数。来源读取和记录转换需要分别观测。

沿用 Java 的固定主机分页、指标窗口及日志窗口执行器，在一次来源端口调用周围记录 SourceRead。每次 attempts=1，completed+failed=1；成功保存完整返回数量，失败保留 received=null，只保存闭合原因和读取时间。端口内部可能进行多次元数据与分页请求，这些请求不是本字段的分母。转换统计及原输出证明继续独立。

来源元数据在历史读取前后校验。来源对象、键、值类型或单位变化均继续拒绝输出，并将已有 SOURCE_CHANGED 细分为闭合原因。原始异常、来源键、单位正文、端点、凭据和样本内容不进入诊断。主机分页没有指标键/值类型/单位钉住关系，不能声称这三类变化。

复用现有 V049 的有界 JSON 元数据。无新数据库、迁移、启动单元或执行后端。200 条本人容量在来源 IO 前检查；写入时再检查当前代数、容量和版本。主机私有逐实体见证与完整返回数量一致，并继续在读取时执行当前对象范围授权。

旧 13 字段记录可读；公开 JSON 在未实测时省略 sourceRead，不重写历史。新字段为闭合、可选对象，纯展示组件不能发起来源读取。报告和 UUID 详情继续经过可信身份、本人、工作流固定版本及当前目标权限门禁。发现损坏元数据即失败，禁止静默返回空列表。

排队时间必须有实际入队和开始执行两个观测点。本阶段执行器没有该观测点，queueWaitMillis 仍为 null；窗口迟到时间不能作为排队时间。来源失败比例仅适用于同一组实测端口调用，不与转换拒绝、输出未知等比例相加。
