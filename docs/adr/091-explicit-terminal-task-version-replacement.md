# ADR-091：明确替换已停止的固定任务版本

状态：已实现并完成本机真实联测与主平台部署；完整S7继续。

正常停止或来源检查失败的指标、日志任务以前只能恢复原版本。来源配置或映射发生不兼容变化时，原版本恢复会失败，而新发布版本也不能启动。主机扫描尚未完成的检查点存在相同限制。

用户明确在更高的发布版本执行 START 时，可以替换 STOPPED/FAILED 的原固定任务。新任务沿用整个流程的控制代数，增加一代并重新取得受信授权；不继承原游标、批次数量或授权。运行中的原任务必须先停止。原待处理批次只有明确 FAILED 才能被替换；主机失败批次还须没有任何已确认实体。READY、IN_FLIGHT、UNKNOWN 不允许以版本升级绕过原结果处理。ABANDONED 仅在原终止回执和 UNKNOWN 父批次一致时允许新版本启动。

替换前把原任务的状态、代数、更新时间、错误类别和待处理批次 UUID 写成不可变版本快照；主机任务另保存原已停止/失败周期任务的同类状态。快照不保存授权、分页游标、源记录、指标值或日志正文。原输入、批次、诊断、控制回执和终止回执留在既有表中。快照和新任务及控制回执同事务提交，授权签发失败回滚；200 条本人容量在签发授权前检查。原 UUID 重放返回原受理结果，不增加历史或重新授权。

V051 在既有 PostgreSQL 增加一张有界元数据表，两个版本外键限定原版本和替代版本。领域层不依赖数据库或框架，既有四启动单元不变。快照不能启动执行器，没有遥测逐点持久编排。当前代数检查仍是单执行器机制，不替代分布式租约和 fencing。

按版本查询持续指标/日志状态时，历史版本不返回当前任务，新版本通过独立的 control.generation 发起 START。历史运行质量从不可变快照恢复原状态，读取时仍检查当前可信身份、版本、批次父对象和实体范围。历史版本不可通过 RESUME 或降级 START 重新成为当前任务；主机旧周期任务覆盖后的历史状态也从快照读取。

快照针对版本替换，未扩展为同版本每次运行的完整历史。新版本开始读取新的指标/日志时间窗口，或重新扫描资产；操作者需据输出语义评估重复读取，系统不声称原批次被撤回。单次样本 UNKNOWN、阈值告警、完整回放、保留/容量及生产授权仍为后续工作。

回滚前停止相应应用并导出终态历史，再执行 V051 对应回滚文件。回滚会失去该表的历史投影；不会删除版本、原批次或输出内容，也不能据此恢复旧版本执行。实际检查见[验证报告](../VALIDATION-REPORT.md)。

持续日志仅对明确未写入的拒绝允许恢复/替换。成功写入后的回读失败保留UNKNOWN，V052的私有rejection_known仅由修正后的执行器在明确拒绝时记录；旧记录默认false，不改其原结果体。公开resumeAllowed反映该门禁。旧不确定拒绝的质量投影与显式处置已在[ADR-092](092-legacy-log-outcome-uncertainty.md)实现，原FAILED仍不作为未写入证明；原终止父对象兼容该不确定旧结果。
