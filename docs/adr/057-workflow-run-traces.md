# ADR-057：有界工作流运行明细

状态：已实现，验证范围见 VALIDATION-REPORT 第73节。

## 问题

v2工作流已持久保存运行计数，但逐条节点结果只在当前响应中，刷新后无法定位解析/校验失败。用户要求像流水线日志一样查到成功与失败记录。

## 决策

沿用现有Java平台及PG integration.workflow_run，在JSON回执中追加可空trace；无新服务、表或数据库。每次合法输入完成确定性执行时，在原CAS事务中原子保存回执及最多5条、每条4–16个节点的元数据。trace包含来源/模型pin、原批次ID、开始时间、执行毫秒数、上游状态/缺Raw/截断，以及每条记录的节点ID/类型、OK/ERROR/FILTERED/SKIPPED、字段与闭集错误码。执行耗时覆盖来源读取和转换，不含回执事务保存。

禁止把输入值、输出值、节点配置、自由文本异常、Token写进trace。合法样本内的转换失败继续按记录执行，失败/过滤后其他节点必须SKIPPED。服务端及Web检查节点顺序、行号、终态、三类计数一致性、来源和只读标记；损坏数据失败关闭。

GET /api/v1/integrations/workflows/runs/{UUID}只读取本人回执，检查可信身份、source.sync/workflow:*及既有目录读取权限，PG查询同时限定tenant和owner。拒绝查询参数；未知/其他主体/其他租户记录404。最近20项仍返回原有摘要契约，可按UUID读取列表以外的记录。会话变化清空前端结果并取消未完成请求。

旧JSON缺少trace时兼容为null；UI明确旧回执没有明细，不补造错误、不重新执行。保留原每主体200回执容量，满额拒绝，不自动删除。fixture/MANUAL_SAMPLE/zabbix-jsonrpc保持原义。

## 范围与限制

本轮覆盖v2草稿预览/已发布版本只读测试，成功不表示实体已写入。批次大于5条时只能查看参与本次转换的有界样本，来源FAILED/截断/缺Raw不隐去。鉴权失败、非法请求、来源读取失败、并发冲突或持久化失败在执行回执提交之前返回原错误，不生成成功或完整运行记录；没有新增异步任务、请求审计日志、自动重试、生产调度、CMDB全链日志或遥测逐点落PG。

没有存储样本正文，因此历史详情只显示状态与错误原因；当次画布预览仍可查看值，重新执行产生新回执。原v1 Host重放和CMDB更正回执继续使用各自已有页面，本页不冒充统一采集日志中心。
