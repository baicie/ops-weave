# ADR-047：扫描运行记录的有界保留与配额

状态：实现与实际验证见 [验证报告第54节](../VALIDATION-REPORT.md)。

## 问题与决定

`integration.source_sync_run` 是第44–49节的追溯基础：分页读取最近运行、按 `syncRunId` 单条读取、把边界
标签与钉住的映射版本展示给运维。但这些行从建表起只增不减：没有自动清理、没有每来源上限、没有租户总量
配额（第43/49节都把它写成已知缺口）。一个长期运行的部署会让这张表随扫描次数线性增长，而“最近运行”
这个读取语义本来就不需要无限历史。

决定：把扫描运行记录当作**有界存储**处理，预算写在领域里并由两个存储适配器同样执行。

- 每个 `tenant + sourceInstanceId + objectType` 范围最多 `maxRunsPerScope = 1000` 行；
- 每个租户最多 `maxRunsPerTenant = 5000` 行（跨来源、跨对象类型）；
- 配置只能收紧，不能放宽；`maxRunsPerTenant < maxRunsPerScope` 或任何越界值一律按 `INVALID_REQUEST` 拒绝。

清理发生在**打开一次扫描的同一个事务里，且在新行写入之后**：超预算时从最旧的“可删除”行删起。因此
范围会在扫描继续时收敛到预算，而不是每次扫描多留一行。

## 语义与不变量

- **可删除 ≠ 全部行**：仍在 `RUNNING` 的运行、以及被 `integration.sync_pipeline_pin` 钉住的运行永不删除。
  钉子是外键，删掉它要么破坏引用、要么悄悄抹掉这次运行“按哪个映射版本走”的答案。
- **正在打开的运行算预算**：它是真实存储的一行，所以预算是行数上限，不是“预算再加一个活运行”。
- **对账与保留无关**：保留只删历史行，不改写任何存储结果、不退休对象、不补做缺失对账；失败的运行和成功
  的运行一样按时间淘汰。
- **读取不清理**：`recent(...)` 与 `retained(...)` 都不触发 sweep。追溯页报告预算与当前条数，但不会因为
  你看了一眼就删掉你在看的记录。
- **未结束的运行会占住预算**：崩溃或被杀进程留下的 `RUNNING` 行受保护，因此不会因为预算而被悄悄丢掉；
  代价是遗留 `RUNNING` 需要独立的租约/状态修复才能回收，本轮不提供自动修复。
- **一致性口径**：内存适配器用 `startedAt` 加运行 ID 倒序（与游标分页同一全序），持久适配器用
  `started_at DESC, id DESC`。同一毫秒内两条运行谁先被淘汰不属于契约，契约是**行数上限**与**受保护行**。

## 边界

这不提供后台清理任务、跨租户总量治理或备份/物理擦除；`source_sync_run` 之外的业务/授权元数据生命周期
仍见 [元数据留存与备份生命周期](048-metadata-retention-backup-lifecycle.md)。预算不改变“只有已验证快照才
允许对账”（ADR-043）：被淘汰的是运行记录，不是对象或结论。真实 Zabbix、真实模型与人工诊断审阅仍未完成。
