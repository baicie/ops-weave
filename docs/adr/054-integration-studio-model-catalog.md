# ADR-054：内置及自定义模型驱动的接入工作台

日期：2026-09-27。状态：采纳；第68节已实现模型定义/版本/清洗预览切片，整体工作台尚未完成。

## 背景

用户明确首版体验为数据源中心 → 配置抽屉 → 确认进入清洗转换画布 → 平台数据模型，并要求实体关系管理页面与以后AI协助的扩展位。用户进一步确认首版支持自定义实体类型、字段和关系类型，同时必须先有内置实体和指标。

当前Host PipelineDefinition v1在Schema与Java域同时限定六节点/五条边，仅支持displayNameField选项；制定本决策时catalog为骨架，Relation只有概念和表原型；第68节已增加模型定义能力，关系实例仍待实现。已有类型字符串、attributes或画布外观不能算作自定义模型/关系管理交付。

## 决定

1. 内置模型与指标包作为默认起点；自定义类型和租户字段扩展同为首版能力。首批复用已有CPU用户态占比、内存可用比例、uptime语义和接入证据；其他类型/指标必须区分定义、连接器和实际数据是否可用。
2. Java catalog拥有版本化实体/字段/关系类型与指标语义，inventory拥有实例/关系/观测；integration拥有来源、节点/映射定义和执行。沿用现有服务与PG，不增服务、数据库或任意代码执行。
3. 来源中心与配置抽屉创建有版本、受权的多来源实例及私有流水线草稿；确认不启动同步。凭据只使用受控引用或专用只写录入，不能进入画布、Prompt和普通日志。
4. 画布是规范化PipelineDefinition的编辑视图，业务定义与布局分开；以新增v2承载确定性转换和固定目标模型版本，不扩写或重算旧v1发布内容。
5. 模型和关系类型发布不可变版本；扩展、停用、兼容性检查及明确迁移避免破坏既有Entity/Metric/Incident/Evidence。服务端强制Schema、权限、资源范围和发布门禁。
6. 关系类型在模型中心定义；实际关系在独立页面按受权实体维护，保留来源、有效时间、观测及撤销历史；拓扑只展示有依据的受限数据。
7. AI只预留侧栏和建议Patch边界。将来建议固定草稿基线、不得带任意代码，逐项接受后重新校验/预览；不直连来源、不发布、不执行运维动作。现有Incident只读诊断不自动扩权。

## 影响与实现顺序

先内置+自定义模型及版本，再来源中心/抽屉、v2转换与预览、编辑画布、关系实例及拓扑，最后完成新首版整链。详细页面流程、兼容策略与OW-ST01–07验收见[工作台设计](../architecture/integration-studio.md)。

本决策替代ROADMAP中将接入画布仅列为远期可选的优先级；保留确定性优先、服务端权限和Copilot实际实现后置的约束。新增需求不自动关闭原M0–M4验收；旧约91%估算不能套用于扩大后的首版范围。本次不修改运行契约或产品代码，不宣称已具备新能力。

第68节实现约束：模型目录暂复用entity.read/entity.manage，但同时要求catalog:*资源授权（可信tenantWide也可）。定义与实例授权分开，entity:*不能单独修改目录。内置只允许复制成新custom.*类型，租户overlay后续实现。当前只允许兼容修订，不提供破坏性迁移或删除发布版本。
