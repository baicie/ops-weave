# ADR-080：固定主机工作流的有界周期采集

状态：已实现；实际验证结果见验证报告第118节。

固定主机工作流已有单轮扫描、原批次恢复和确认游标。周期运行复用该执行器与现有 PostgreSQL 日志，不增加启动单元、数据库或外部编排服务。

周期记录固定工作流版本、语义摘要、名称映射和60–900秒间隔。首次启用立即创建扫描；整轮确认完成后，以完成时刻加间隔设置下一次采集。错过的时段只触发一轮，不建立追赶队列。每个主体最多20个周期记录、200份控制回执；启用和恢复使用前180个回执位置，为停止保留20个位置。

每次启用或明确恢复最多处理20批。主机批次成功或已尝试写入时扣减本次额度；委托运行同时沿用服务器签发的原授权ID、有效期与已消耗额度，下一轮不能自行续权。每次扫描及每条写入重新检查当前可信身份、对象范围、版本和来源配置。开发与委托任务隔离。

V045只保存周期元数据和不可变控制快照。整轮统计与最后一批确认在同一事务中更新，避免确认后授权过期丢失最近成功记录。原主机行、清单游标和结果不明的写入保留在V043的有界私有批次日志中。周期START不能跳过未完成扫描；RESUME重新申请短时授权，并沿原批次继续。来源失败或写入结果不明会暂停周期，执行器不自动恢复。已停止、已失败的周期仍可查询原控制回执。

停止周期与停止当前扫描在同一租户事务锁内完成。当前扫描已结束时仍能停止未来采集。手动停止正在运行的扫描也停止其周期；普通扫描START/RESUME不能抢占已启用周期。任务代次或固定版本不匹配时周期失败，不接管新任务。

当前为单执行器实现。进程内并发额度和 PostgreSQL 事务锁不等于分布式租约、fencing或多副本容量控制。扫描缺失记录不会自动删除资产；完整快照生命周期、质量恢复、长期授权和保留策略仍需单独设计。
