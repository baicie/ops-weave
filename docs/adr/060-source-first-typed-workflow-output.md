# ADR-060：来源先配置，工作流选择实体、指标或日志输出

日期：2026-10-01。状态：已接受；§80实现有界转换预览、保存与发布，真实连续采集和存储写入尚未接通。

## 问题

来源中心把每个来源强制绑定实体模型，并在确认时生成实体工作流。日志和指标因此被当作资产属性，日志正文还会经过默认TRIM。来源连接、数据处理、输出语义需要独立配置；已有实体版本与历史摘要必须兼容。

## 决策

来源确认只要求名称、说明、来源描述符和当前连接摘要。新界面不传target；SourceSetup.initialTarget及确认响应workflow为null，保存不可变来源回执后进入输出选择。首次显式保存工作流才创建草稿。旧客户端可以继续传合法ENTITY模型pin，沿用原确认与草稿事务、摘要和回读行为；来源确认幂等性不随后续工作流编辑变化。

v2定义target使用闭集联合：旧ENTITY形状仍为{id,revision,digest}，LOG/METRIC分别为{kind,schemaVersion:"1.0"}。不为遥测伪造实体模型或目录digest，实体输出仍校验发布模型版本及目录权限。来源与工作流入口要求source.sync；没有entity.read的调用者可以管理有权来源及遥测工作流，模型目录返回空列表，实体创建仍拒绝。身份、租户与来源对象范围来自可信会话。

LOG固定eventTime、body及可选severityText/serviceName/traceId/spanId；正文保留首尾空白，时间带时区并规范化UTC。METRIC固定timestamp/metricKey/value/metricType及可选unit，首版只接受GAUGE，不把SUM、累计量或速率混为同义。数值有限、最多12位小数、绝对值不超过JS安全整数范围。规范化Schema和显式Fixture样例放在contracts，不增加日志数据库。

MANUAL_SAMPLE可以预览三种输出；已有ZABBIX_HOST批次只提供主机实体元数据，前后端和Schema均拒绝以其作为日志或指标输入。来源卡片可用不等于已连接。白名单算子仍固定版本1、单链4–16节点，没有任意代码、SQL、HTTP、循环或模型转换。

遥测模板含SOURCE→MAP→VALIDATE→OUTPUT，不默认添加TRIM；用户显式添加TRIM时界面提示其也会裁剪正文。切换输出重建字段和默认节点，清除旧预览，必须重新保存和预览。发布仍需要同digest的15分钟内有效回执、至少一条通过且零拒绝；发布、测试运行与真实启用分开。

## UI与运行记录

继续使用React、shadcn/ui、既有shadcn-admin主题及X6适配器。增加来源/处理/输出阶段、三种输出选择卡、对应字段和格式校验、输出边界以及节点输入/输出预览。节点输入输出只显示本次响应；运行历史持久化输出类型、节点状态、失败字段与闭集错误码，不记录样本、日志正文或输出值，不以持续采集吞吐量包装样本计数。

## 后果与边界

复用四个启动单元、现有PG及私有来源/草稿/版本/运行表，无迁移、依赖升级或历史回填。ENTITY摘要算法和线上JSON形状保留，旧来源可继续打开原实体工作流。遥测格式版本参与语义digest，但不会授予存储或采集权限。

所有预览和发布版本测试为dry-run，writesPerformed=false。当前输入仍是有界平面记录，尚无Grok/多行原始日志解析、连续日志采集、指标存储写入、日志索引、实体关联、自动启用、任意多实例编辑、分支并行或AI建议执行。未来真实接入应保留控制与高吞吐数据链路分离，新增运行语义需独立契约、容量和真实端口验证。

实际检查见[VALIDATION-REPORT §80](../VALIDATION-REPORT.md)，使用见[来源中心](../runbooks/source-center.md)与[工作流](../runbooks/workflows.md)。

### 2026-10-02 界面修订（§84）

按用户要求优化接入流程。移除来源后的输出选择卡，进入默认画布并准备未保存的本地流程；输出类型、模型 pin 放到输出节点配置。手工样本在实体目录可用时以实体开始，否则以日志格式开始；Zabbix Host 仍只允许实体，目录缺失明确报错，不将该来源转成遥测。默认模板不是服务端已保存配置；旧来源、草稿和发布版本按原记录打开，不改契约、摘要或持久化规则。所有写入仍由原显式保存/预览/发布操作发起。
