# ADR-081 模型版本检查与固定引用

- 日期：2026-10-04
- 状态：本机实现；整体数据平台目标继续
- 前置：[模型目录](054-integration-studio-model-catalog.md)、[工作流](055-native-transform-workflows.md)

模型发布已经在租户事务内检查追加兼容性，但用户此前只能在提交时得到错误，无法查看差异和旧版本引用。本次在现有 Java 平台增加只读发布检查与固定版本引用接口，沿用四个启动单元、现有 PG 表和 `contracts`。不增加后台框架、数据库或动态代码执行。

发布检查接收自己的已保存草稿引用、编辑版本和摘要，重新读取候选内容与最新发布版本。返回完整候选/基准 pin、检查时间、字段及端点差异和兼容性原因。保留既有规则：发布版本连续，类型及关系端点/基数固定；旧字段类型、必填、范围、长度、枚举不可更改或删除，只允许新增可选字段及调整显示名称/说明。数值边界使用数值相等，枚举差异使用无歧义表示。新类型的首版可以定义必填字段。

检查是当前元数据报告，各项读取不构成跨目录和任务的原子快照。它不授予发布权限、不锁定后续发布，也不替代发布事务中的 CAS、摘要、最新版本和端点校验。其他操作员在检查后发布新版本时，原提交仍会冲突；历史资产和任务不会自动迁移。

引用查询必须先授权并解析明确的模型版本与摘要。返回固定此版本的已发布关系类型、可读取的工作流发布版本和本人的草稿；关系标记起点/终点，工作流标记输出及实际目标字段。字段从 MAP 的值和已校验处理字段获取，不能将来源键冒充模型字段。任务摘要仅返回本人的同工作流版本/摘要主机扫描和周期状态，不含原记录、恢复游标、授权、凭据或其他人的任务。

模型目录依旧要求可信 `entity.read` 与 `catalog:*` 范围。工作流引用通过既有 `source.sync`、工作流及来源元数据边界过滤；没有工作流读取资格时明确 `workflowsAvailable=false`，不能报告租户全局零引用。明确权限拒绝可过滤该引用，存储或来源失败返回失败，不能静默替换为空列表。最多 50 项，截断标记保留；关系查询定向到模型 ID/revision，不依赖目录前 50 项，工作流沿用既有有限存储容量。

前端将列表、差异和引用展示抽成纯组件，请求与身份/取消生命周期留在容器。保存干净草稿后只自动检查一次；编辑使发布资格失效，失败需人工重查。固定引用按需展开后首次一次读取，关闭/主题/尺寸不触发重复请求。正式发布仍是用户点击。模型及字段链接固定 ID/revision，目录外自定义版本使用明确版本接口，缺失不得替换最新版本。表格局部滚动，完整标识换行，关系图按需展开。

未实现破坏性模型迁移、自动工作流重绑定、运行任务升级、全局依赖分析、历史资产重写和跨服务一致快照。实际验证见[验证报告](../VALIDATION-REPORT.md)第119节。
