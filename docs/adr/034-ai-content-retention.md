# ADR-034：AI 正文留存、显式清理与不可重用的运行标识

状态：已实现本机切片。2026-09-26。依赖 ADR-022/023/030/033；验证见报告第 40 节。

证据的 24 小时读取有效期不能替代存储留存。直接删除 AIInsight 或 Evidence 行会释放运行 ID、会话唯一约束和引用关系，使旧请求可能再次进入模型链，也会失去旧资源的授权范围。

本次只清理 `ai_control.ai_insight`、`ai_control.evidence_snapshot` 的过期正文，以及超出配置期限的 `audit.tool_read_call`。V019 为正文增加创建/过期索引与 `retired_metadata`。清理将 snapshot 置空，原主键、会话唯一约束、引用外键继续存在；标记仅保留租户、主体、Incident/实体/指标范围、时间和请求摘要，不保存问题、结论、厂商载荷。旧读取按当前权限与原范围复核后返回 410；原输入重新提交也不重新调用模型，变更输入或主体返回 409。

运维通过 `OPSWEAVE_AI_RETENTION_POLICIES_FILE` 提供有界租户策略。默认关闭，内存存储不模拟清理。预览和执行均要求可信 Principal 的 `ai.retention.manage` 与 tenant-wide scope；普通诊断权限、菜单、模型输入或 Runtime 委托不能授予它。策略中 allowPurge=false 可仅预览。无定时任务、批次循环、任意 SQL/HTTP 或新 Tool。

预览固定到整秒 asOf，有效 120 秒，摘要覆盖 actor、tenant、完整策略摘要、三类候选 ID/字节数/hasMore。摘要是确定性的内容绑定，不是认证凭据。每类最多 100 条，按创建时间与 ID 排序。只有正文创建时间严格早于配置截止且过期时间严格早于 asOf 才能清除；审计开始与最后完成时间均须早于审计截止，关联活跃会话不清理。保留 Incident 按数据原始 incident_id 精确排除，不自动扩展合并关系。

POST 在 PG 租户事务锁内重算并锁定候选，摘要变化拒绝。正文清理、审计删除和回执原子提交，提交前再次读取配置并检查预览时限与线程中断。配置文件不是数据库锁的一部分：采用本请求提交前检查时的策略快照，检查之后的外部文件变化由下一请求生效，不宣称文件变更与事务线性一致。紧急保留时应先停止清理入口并等待在途请求结束，再更新配置。

同租户/原操作者/相同 requestId 与请求内容返回原回执，包括后续配置被关闭的情况；这不再执行清理。其他主体不可读取回执，复用 ID 但改参数返回 409。回执每租户最多 10000 条，达到上限拒绝新清理，不自动删幂等依据。控制台明确预览与人工勾选确认，未知结果保留 requestId 只供查询，不重试或自动执行下一批。

共享 ToolExecutor 的四并发/15 秒、PG 每条语句 3 秒/锁等待 2 秒继续适用。内容 JSON 大小、配置 256 KiB、最多 100 租户/每租户 1000 个保留 Incident 均有边界。迁移对既有正文回填时间；PostgreSQL 微秒精度与严格截止比较最多延后纳秒边界行，不提前清除。

这不是全平台的数据治理完成：费用账本（包括未知费用）、会话与授权元数据、引用边、保留标记、Incident、Raw/Observation、资产和重放记录没有时间清理。正文逻辑字节数不是磁盘回收量；旧版本、WAL、复制与备份介质需要独立的维护与备份生命周期。未新增生产调度、对象存储、数据库或部署承诺。
