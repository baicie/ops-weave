# ADR-099 · 有界历史日志投影重建

状态：代码实现，最终实际验证与部署以[验证报告](../VALIDATION-REPORT.md)第137节为准。

已有完整日志窗与受控指标重建提供可复用的固定版本、共享预算和原请求机制。日志重建复用原 Java 来源/编译计划和 ClickHouse 批量端口，四启动单元不改；无新数据库、线程、框架依赖或动态脚本。

范围检查与确认输出分开。前者先持久 PREPARING，读取过去24小时完整60秒/最多1,000条，转换后固定输入/输出摘要与接受位置。后者先持久唯一 PENDING，再重新读取同一范围并完整匹配，在输出前重查当前可信身份和固定版本。范围10分钟有效，原始历史来源重新读取不冒充已保留的原始快照。

独立 workflow.replay 及原来源/连接/发现/实体门禁保持。日志读写使用已有 log 资源范围，不把工作流菜单或相同权限名称当作日志对象范围。缺少写权限不能准入来源检查，默认身份不增加任何权限。读取原元数据、正文及核验仍需当前读范围；身份不从命令或证明中的字段构造。

沿用既有 PG 的 V057 两张证明表、父版本外键、每个选择唯一执行和租户事务锁。原值不入PG，不逐记录持久编排。日志引擎 V003 独立表隔离重放，构建时固定表名只允许原持续表与重放表两项；当前日志应用账号只需该表 SELECT/INSERT，不授予 DDL。原持续任务、批次、授权及checkpoint保持。

输出使用原批量端口，一次写后独立精确回读。写入已发生后回读失败必须 UNKNOWN，不能以读取拒绝降为 FAILED。显式核验只读原输出，没有来源/写入端口调用；受理不足180秒的 PENDING 保持，时间保护不是租约。空完整范围不写输出。原 UUID 重复不重读、重写、换输入或更新授权。

正文由显式输出查看入口读取，每页50条，复用已有完整窗口数据协议和文本记录组件。范围检查、展开、选择记录、主题/尺寸变化都不自动读取正文。当前读取完整性与原回执分开；接受索引/纳秒位置、父范围与原摘要必须匹配，失败保留未知，不补空成功。

Web共享纯 WorkflowReplayPanel，指标/日志 API 和请求容器保持各自闭合协议、原 UUID、会话取消与待确认门禁。展示和业务请求分离；局部动作区使用自然宽度与窄屏换行。普通日志不记录原文、秘密、认证或请求正文；开发证据和截图在仓库外。

200个本人范围及20条列表仍是开发上限。生产留存/容量、未知重放处置、覆盖修复、资产重放、通知、公平调度/轮询完整性、租约/fencing/HA与生产身份持续链仍需独立完成。本节不将前台幂等称为跨存储 exactly-once。
