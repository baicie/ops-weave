# ADR-090：明确终止固定任务恢复并保留输出不确定性

状态：已采纳，验证结果见实现状态及验证报告第128节。

UNKNOWN 表示输出结果不明。长期暂停的任务需要明确结束恢复尝试，但结束不能证明未写入，也不能删除已写入内容或把批次改成成功/失败。关闭浏览器或丢失 HTTP 响应也不能取消服务器已经受理的命令。

在既有 Java 应用服务增加闭合显式命令与不可变回执，复用可信身份、原固定版本和已有事务。服务只有 WorkflowStore 与 Clock，没有来源、输出、核验、通知或授权签发端口。受理将任务置 ABANDONED、代数加1并撤掉后台授权；确认游标和数量不动，原批次保持 UNKNOWN。主机停止同版本周期，并保留原分页/checkpoint；公开回执的主机游标固定 null，不能泄露私有来源清单摘要/总数。

V050 在已有 PG 增加恢复回执表，不存原始输入或遥测正文；200条本人容量约束与任务修改处于同一事务。原 requestId 重放返回原内容，权限和原证明每次重新校验。确认输出的并发返回不得覆盖已终止任务或把原 UNKNOWN 批次细化为确认；当前状态与代数要在核验返回后再次检查。

同版本恢复禁止，更高发布版本可由用户明确 START，创建新窗口/扫描及新授权。旧批次和回执不改写。持续指标/日志按版本状态查询分别返回固定版本数据和用于控制的全流程代数；历史质量报告从原不可变回执保留终止事件，不能因当前任务被替换而丢失。

请求容器和展示组件分开。前端校验原 UUID、带命名空间的摘要、固定版本、原批次、代数及数量；非法回执按待确认处理。只在用户明确查询后获得原404时允许原内容重发。未知命令阻止页面关闭/内部版本切换/容器折叠；身份清理和取消保持。

选择不增加执行框架、启动单元或数据库，也不将 ABANDONED 加入业务输出状态。历史修订/重放、单次样本放弃、保留/生产容量及租约/fencing/HA仍需独立工作。回滚前必须停止使用新状态的应用并保全回执；不能把 ABANDONED 自动翻译成旧版本可恢复状态。
