# ADR-076：任务控制原回执与未知结果确认

日期：2026-10-04。状态：实现启动/停止的受理回执；固定来源批次、业务输出恢复及生产运行门槛继续。

启动请求可能已经提交，但浏览器只收到连接失败。若刷新任务后以新的代数再次启动，会创建新的后台授权或处理起点。停止回执也可能在后续任务已经启动后才被查询。控制命令必须有独立身份，原受理结果与当前任务状态必须分开。

使用现有Java平台、纯领域服务和已有PostgreSQL。新增V041低频控制回执表，不增加数据库、执行服务或启动单元。请求UUID由客户端一次生成，固定操作、工作流版本/摘要、字段设置及expectedGeneration。服务端按可信tenant和owner隔离，计算带长度边界的规范摘要；请求不能指定租户、权限或后台授权。

任务变化和受理回执在同一现有租户事务内提交。相同请求键和内容返回第一次的不可变回执，不重新签发授权、不推进代数、不采集或输出。相同键但不同操作、版本、摘要、设置或代数返回409。事务回滚时任务和回执均不提交。拒绝受理的权限、版本、容量或代数检查没有成功回执；本方案不是所有失败请求的审计账本。

公开回执为requestId、operation、commandDigest、createdAt和task快照。task只包含公开授权摘要；独立私有Schema保存原授权引用。回执中的RUNNING或STOPPED表示当时受理结果，不能替代当前任务。GET原回执只读，不执行动作；重放仍要求当前可信身份具有对应工作流读取范围，但不要求重新申请后台委托。不同所有者或租户不能读取原回执。

每个所有者最多200份受理回执；新启动达到180份即拒绝，为最多20个任务留出停止位置。停止只接受RUNNING任务，失败停止不消耗位置。原回执查找先于容量检查，满额仍可查询或重放。没有自动删除、隐藏重试或自动换键；保留期和显式清理另行设计。

代数保持单调，不通过清零规避容量。新启动在expectedGeneration达到999999时拒绝，为停止预留代数；旧RUNNING任务即使代数为1000000仍可停止到1000001。最后一代只允许STOPPED，不能再次启动。这一兼容余量避免已有任务因新上限变得不可停止。

前端保存原UUID与完整输入于当前身份的内存。未知响应锁定修改/版本切换/关闭，显示查询入口，不自动查询或重发。只有显式GET 404才允许按原键原内容重新提交或放弃确认；放弃不取消服务器命令，必须重新读取当前状态。收到合法回执后另读当前状态，不能把旧快照写回状态。身份变化或403清除私有状态，迟到响应丢弃；不持久到浏览器存储。

内部HTTP控制契约同步升级：POST启动/停止现在必须带requestId，响应从Task变为Receipt。旧无UUID客户端返回400；客户端与平台须成对升级，GET任务/执行格式兼容。迁移仅追加表，旧任务可读取。回退须先确认原命令结果并停止必要任务；回退脚本不自动删除回执，也不作为未知命令的取消方式。

本次仅解决控制受理的原结果确认。资产输出的未知结果、失败批次恢复、固定配置来源、指标/日志持久输出、HA租约/fencing和生产身份仍未交付，不能宣布S5完成。契约见[任务控制](../../contracts/workflow-runtime-control.md)，操作见[回执确认](../runbooks/workflow-runtime-control.md)，实际检查见[验证报告](../VALIDATION-REPORT.md)第114节。
