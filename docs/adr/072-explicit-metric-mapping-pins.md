# ADR-072：采样映射的完整固定与显式维护

日期：2026-10-04。状态：已实现并完成本机验证；生产迁移与容量仍待验收。

旧指标绑定只记录mappingRevision，不能分辨相同版本号下改变的来源键、范围或转换规则。若同步或读取直接使用部署中的最新定义，既有绑定的含义可能被悄悄替换。本次为来源采样增加id/revision/digest三项固定引用，摘要覆盖完整MappingDefinition语义；来源指标发现复用相同计算，保持已有摘要不变。

继续使用Java领域与应用层、既有telemetry.metric_binding、PostgreSQL和四个启动单元。V040新增nullable mapping_pin及按tenant/owner/requestId唯一的维护回执表。迁移保留旧绑定为未固定；同步既有元数据不采用新pin，内容未变不增加绑定版本。新建绑定由受控映射生成pin。已经固定的绑定不能被普通同步替换成不同pin，已被固定绑定引用的指标单位、类型和维度不能被普通定义更新改写。

维护命令只接受requestId、expectedBindingVersion及登记映射pin。服务端检查可信Principal的metric.read、entity.read、source.sync和source.configure及对应对象范围，选择服务器登记的完整定义；不接受请求中的规则、身份、地址或凭据。旧绑定首次固定须匹配原版本、转换与固定维度。后续升级限于同一映射id的更高revision，并保持标准指标、单位、类型与维度定义兼容。同id/同revision但不同摘要拒绝；不是任意规则编辑器、降级或历史重算。

PostgreSQL在租户事务中序列化元数据更新与维护，校验当前绑定版本，原子保存新绑定与不可变回执。相同主体、UUID和命令返回原结果，不再次更新版本；原结果在目录升级或绑定退役后仍可按当前读取权限查询。同UUID不同命令冲突。每主体最多200份回执；锁等待5秒、SQL语句10秒。内存模式使用同一存储监视器及回滚快照，不宣称跨进程一致性。

列表先在存储中按source/entity/metric范围筛选，再扫描最多201份授权候选并展示20份，超过预算明确截断；不能让范围外的记录挤掉范围内绑定。单项及原请求GET继续检查当前绑定与原回执范围，不泄露其他主体的回执。

真实Zabbix历史读取在取秘密或发网络请求前检查完整pin。缺少pin、登记目录失配以及来源元数据不兼容均拒绝，不静默改用当前规则；读取后再次比较完整绑定与指标定义，发生变更丢弃整页和游标。同步、维护与读取各自保持原预算和明确失败，无自动重试或Fixture回退。维护只修改平台元数据，不读来源、不补采指标点、不写工作流或授予后台权限。

Web的MetricMappingPanel管理授权读取、CAS、缓存和原命令；MetricMappingTable展示列表，MetricMappingDetail展示完整来源键、标准指标键、转换、范围、维度与摘要。两者不发HTTP。右侧抽屉首次打开读取一次，缓存返回不重读，刷新显式触发。结果不明锁定选择、关闭和新提交，只允许查询原请求；核对UUID、命令摘要、前后pin、绑定版本及完整语义后解除。明确并发拒绝要求重新读取，身份变化清空私有状态。完整指标标识可进入准确的指标定义。

这个pin固定的是来源绑定与当前登记采样规则。旧历史点不因此获得完整摘要证明；现有历史响应和Worker输出标记仍沿用原有字段。工作流内联MAP已进入工作流语义摘要，本次没有加入不参与执行的映射引用，也没有把独立标准指标目录接入工作流。模型字段发现、标准指标工作流、可信可撤销后台身份、持久固定批次、真实输出和质量恢复继续实施。实际检查与失败记录见[验证报告第110节](../VALIDATION-REPORT.md)，公开协议见[维护契约](../../contracts/metric-mapping-maintenance.md)。
