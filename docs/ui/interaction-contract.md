# Interaction Contract · UI-INTERACTION-001

## 用户动作约束

- 每个页面必须定义主任务、默认焦点、打开路径、退出/返回路径、主要动作、危险动作和行为反馈。
- 查询动作可以重试，但受限查询必须携带时间窗/数据范围；Mutation 的超时结果为 UNKNOWN 时，禁止未经原请求 ID 回查就自动重复提交。
- 详情抽屉/对话框关闭时，键盘焦点回到触发点；敏感抽屉在登录身份切换时清除数据。对话框只用于必须打断当前工作流的确认。
- 加载由数据容器所有，展示组件不得发起权限决策。API 403/401/429/5xx 不应都归类为空结果。

## 必须建模的状态

| 类型 | 呈现要求 | 可以做什么 |
|---|---|---|
| `initial` | 清晰的开始指引，不能显示旧会话数据 | 连接/加载 |
| `loading` | 骨架或低噪加载状态，保持原布局 | 可取消（需要时） |
| `ready` | 真实结果、上下文、时间范围 | 查看/筛选/钻取 |
| `empty` | 明确“查询完成且没有匹配结果” | 改筛选/改时间 |
| `partial` | 结果不完整的提示及原因 | 缩小范围/重试授权查询 |
| `stale` | 上一次查询时间和失效原因 | 刷新 |
| `error` | 可操作的错误码/重试，而非空白 | 按条件重试 |
| `forbidden` | 授权失败；及时清理敏感数据 | 返回/重新登录，不应泄露摘要 |
| `fixture` | 强调“演示/合成数据”，不能标为真实 | 调试，不能用于质量评测 |
| `unknown-write` | 已请求，结果未确认 | 原 ID 查询状态，不隐式再次提交 |

## 复杂交互分层

### Incident Investigation
- 主内容：事故摘要 + 时间线 + 候选验证。
- 事件选择影响所有有关面板的时间窗/selection，但不得静默改变存储的 Incident 状态。
- AI 查询状态显示 `queued / running / partial / completed / failed / cancelled / inconclusive`，**运行成功不等于根因确认**。
- 每条 Evidence 可打开来源记录或展示可审计的定位条件；查询权限不足应允许安全失败。
- 人工确认根因与关闭 Incident 是两项分离操作。

### Data Source Setup
- Wizard `来源 → 连接 → Scope → 数据预览 → Mapping → 启用`。
- 检查连接无副作用；启用/发布必须有清楚的范围说明与确认。
- 表单失败不丢失用户输入；Credential 可引用但不回显明文。
- 复杂的 Mapping/技术配置移到 Advanced Drawer；不强制一般用户理解版本 pin/digest。

## 可访问性与触控

- 所有控件具备 label（图标按钮要有 aria-label）、可见 focus ring、键盘操作、错误关联（aria-describedby）。
- 非文本图表提供表格/摘要替代；状态与 severity 不只用色点。
- 低运动偏好必须关闭非必要动画；敏感动画不应影响读取时间窗和数据。
- 390px 只读基本工作流必须可用；复杂双栏工作区可以退化为 Tab 页面，不强求小屏上画布全功能操作。
