# OpsWeave V2 Visual System · UI-DESIGN-001

> 范围：Web Console V2 候选规范。系统 Design Token 的替换需要 UI 评审；不要直接覆盖旧控制台的全局样式。

## 1. 品牌气质（用可检测规则，而不是形容词）

产品定位：专业、冷静、可信、以数据和决策为中心的可观测与故障调查工作台。

**视觉层级**：业务状态 > 证据和趋势 > 操作 > 源数据 > 实现细节。视觉要让值班工程师几秒内识别“哪里出问题、我该点哪里、这个结论凭什么”。

**页面外壳**：56px 顶栏、216px 左导航（可折叠为 64px）、24px 内容内边距；主内容必要时 2 栏，右侧 Inspector 默认 340px、在 1024 宽度转叠层或抽屉。**数字是初始设计约束、非保证所有场景统一死板尺寸**。

| Token 类别 | 约定 | 禁止 |
|---|---|---|
| 主色 | 中性表面 + 1 个交互强调色 | 两种以上竞争主色或渐变背景 |
| 语义色 | Critical/Warning/Healthy/Unknown 仅用于状态和少量提示 | 用红/绿装饰普通标题、且不给文本 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 | 同页随机 13/19/27px 间距 |
| 正文 | 14px/1.5；表格 13–14px | 主内容普遍 11–12px 强行塞满 |
| 页面标题 | 24px 600 / 二级 18–20px 600 | H1 多个、字号混乱 |
| 辅助文字 | 12–13px，不取代正文 | 重要警报用极低对比灰 |
| 控件高度 | 常规 36px；紧凑 32px；触屏目标尽量 >= 40px | 同类按钮大小随意变化 |
| 圆角 | 小组件 6px / 大区域 10px | 每个 Card 使用大圆角胶囊 |
| 阴影 | 下拉/浮层可用轻阴影，数据区优先细边框 | 多层强阴影和厚边框 |
| 图标 | 16–18px 为常规图标，仅表达功能 | 各类大图标仅装饰 |

## 2. 表面层级

只使用 `base`、`raised`、`overlay` 三层。常规内容区域避免超过 1 层可见边框；表格本身不套多重 Card。框架 Shell 的背景不应与实际数据争夺注意力。

## 3. 文本与色彩

- 浅色/深色有相应语义 Token，禁止在组件写死文本颜色或背景色；设计稿 Token 候选见 `templates/opsweave.tokens.v2.css`。
- 标准文本对背景对比度目标至少 4.5:1；必要图标、输入框边界、焦点边界等非文本对象至少 3:1。
- 数字使用 `font-variant-numeric: tabular-nums`；时间、百分比、单位排版始终一致。
- 数据密集部分可显示技术标识，但移到次级层、信息面板或可复制的细节区域，不要成为 H1/H2。
- 设计不假设字体资产，优先系统字体栈。

## 4. 页面空间规划

- 每屏一个高优先级任务、一个主要 CTA。页面大标题区域包括 H1、关键上下文、主要动作，不放 6 个同权操作。
- 横向空白应主动服务比较和阅读：一张完整可用的时间趋势图通常比 4 张 KPI 卡有更高价值。
- 不按 API Endpoint 拆 UI；关系密切的内容优先做同一工作台（tabs / inspector / drawer / timeline）。
- 多列表：高频数据保留表头、排序、筛选；长字段折叠或复制；不要将每条数据变成独立大卡片。
- 视觉强调限于一个区域。加载骨架与真实排版尽量同形，减少布局跳动。

## 5. 反模式清单（PR 必须检查）

| 反模式 | 拒绝理由 | 正确替代 |
|---|---|---|
| Card 套 Card 套 Card | 页面像盒子套娃，信息密度被稀释 | Section + 轻分割线 / 表格 |
| 五个同色实心按钮 | 主次不清 | 1 Primary + 次级/菜单 |
| 多个单值指标就铺满 KPI 卡 | 无法理解趋势与时间 | 少量概览 + 趋势图 + 证据 |
| 把后端 ID、hash、游标放在首屏 | 信息优先级错误 | 详情、复制、调试入口 |
| 空数据用 0 渲染 | 严重误导 | No Data/Unknown 状态 |
| 自动为模型结论显示 96% 信心 | 没有真实概率校准 | 证据支持/反证/未验证 |
| 只有桌面大屏好看 | 1024/390 完全失控 | 正式定义响应式退化策略 |
| 永远 `min-height: 100vh`+嵌套多层滚动 | 内容被截断、键盘无路可走 | 明确唯一主滚动与局部滚动容器 |

## 6. 视觉规范交付条件

任何新增页面必须提交：布局图、组件清单、状态矩阵、必要的真实截图、问题整改记录。命名/视觉不能代替内容真实与可操作性。
