# UI 视觉与信息层级

适用范围：所有前端页面、组件、布局与样式的设计和修改，包括 `apps/web-console/**` 及未来的 `apps/web-next/**`。

优先阅读 `docs/ui/visual-system.md` 与 `docs/ui/page-blueprints.md`。

- 先明确页面 Primary Task、视觉焦点、信息优先级与渐进披露；不能把 API 资源名照搬成导航。
- 页面只能有一个主要 CTA（多步骤编辑器可明确说明例外）；其他操作为次级或三级。不要让所有按钮、面板同等醒目。
- 避免 Card-in-Card、连续厚边框、过多阴影、装饰性大图标、状态徽章滥用、超多颜色、无信息量的 KPI；表格与图表以阅读效率为先。
- 使用主题变量和 Design Tokens；不要散落色值、临时 px 魔数、每页自设按钮高度/圆角/字体大小。需要新 Token 时同步扩展文档和双主题。
- 排版层级：H1/H2/section-label/body/caption，页面标题应传达任务；文本对比度要求 WCAG AA 水平（一般正文至少 4.5:1，非文本关键部件至少 3:1），不能仅靠颜色编码状态。
- 设计 1440×900 主桌面、1024×768 窄桌面、390×844 手机只读退化；纵向滚动与侧栏固定/收起要有明确行为。复杂可视化首版桌面优先。
- 视觉变化前后需真实截图；看不到截图不能宣称“观感高级”。
